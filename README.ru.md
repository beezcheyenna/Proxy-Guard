# Proxy Guard

[简体中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · [Русский](README.ru.md) · [فارسی](README.fa.md)

**Блокировка непреднамеренных прямых подключений защищаемых устройств при сбое прокси.**

**Поддерживаемые прокси-клиенты:** PassWall · PassWall2 · OpenClash · Nikki · HomeProxy. См. [совместимость версий и режимов](docs/COMPATIBILITY.md).

Proxy Guard защищает прокси-соединения в OpenWrt / iStoreOS. При включённой защите подтверждённый сбой прокси автоматически блокирует интернет-трафик выбранных устройств, снижая риск непреднамеренных прямых соединений и раскрытия реального IP. Доступ возобновляется после успешных проверок восстановления.

Защищается только трафик выбранных устройств, реально проходящий через этот маршрутизатор. Настроенные исключения для LAN, DNS и управления сохраняются.

<a id="guide-editions"></a>

## Версии

Standard защищает прокси-соединения на маршрутизаторе без облачных компонентов. Pro добавляет управление доступом к VPS и требует отдельного Linux Agent; Cloudflare необязателен.

| Возможность | Standard `0.3.0-16` | Pro `0.3.1-3` |
| --- | --- | --- |
| Защита при сбоях, загрузке и по расписанию | Есть | Использует Standard |
| Мастер, самопроверка, журналы и сторожевой процесс | Есть | Использует Standard |
| Авторизация домашнего IP и правила выбранных портов VPS | — | Есть |
| Аварийный SSH и удалённое обслуживание | — | Отдельное включение и разрешение |

Скачать: [GitHub Releases](https://github.com/beezcheyenna/Proxy-Guard/releases) · [Инструкция по установке](docs/USER-GUIDE.ru.md#guide-setup)

> **О выборе Pro:** Для обычного использования рекомендуется Standard. Pro не рекомендуется без особой необходимости, например управления доступом к VPS или использования других его расширенных функций.

## Возможности

- Защита при сбое прокси: проверка соединения через локальный SOCKS, необязательная сверка выходного IPv4 и проверка UDP.
- Блокировка Интернета для выбранных клиентов: IPv4/IPv6 и TCP/UDP в обоих направлениях, включая установленные соединения, проходящие через маршрутизатор.
- Защита при загрузке и по расписанию: блокировка при запуске, ежедневные или еженедельные интервалы и фиксированное смещение UTC.
- Мастер настройки и самопроверка: рекомендации области защиты, проверка после применения и откат неподтверждённых изменений.
- Обновляемое состояние и журналы событий: контроль служб и журналов клиента, надзор за процессами и ограниченное автоматическое восстановление.

## Установка и первоначальная настройка

1. Установите подходящий IPK Standard через страницу пакетов LuCI. Для функций VPS добавьте совместимый пакет Pro.
2. Откройте «Службы → Proxy Guard», пройдите мастер и проверьте SOCKS, клиент, входные интерфейсы, область IPv4 / IPv6 и исключения. Сначала включите проверки в режиме «Только наблюдение», сохраните и примените настройки, подтвердите по запросу и проверьте результаты.
3. Когда будете готовы к блокировке, выберите режим защиты и снова нажмите «Сохранить и применить». После успешной самопроверки **подтвердите в течение 30 секунд**. При ошибке самопроверки или отсутствии подтверждения настройки откатываются. Обычный сбой прокси обрабатывается процедурой защитной блокировки.

После установки защита, проверка выходного IPv4 и расписание отключены. Редактирование меняет черновик; «Сохранить» сохраняет его, а **«Сохранить и применить» отправляет изменения**. В настройках можно повторить мастер, загрузить последнюю подтверждённую конфигурацию или редактировать исходную UCI.

## Совместимость и область защиты

Маршрутизатору нужны **opkg, LuCI и firewall4/nftables**. Совместимость клиента зависит от версии, ядра прокси и режима перенаправления. Linux Agent для Pro требует Python `3.10+`, nftables и systemd / OpenRC.

- Защищается только трафик, реально проходящий через маршрутизатор. У шлюза без NAT в одной подсети обратный трафик может идти в обход. Соединения самого маршрутизатора не входят в область защиты клиентов.
- LAN, DNS и управление сохраняются согласно исключениям. Плагин не меняет NAT, интерфейсы, системные маршруты, DNS и настройки прокси-клиента.
- Этот IPK не поддерживает APK и системы только с fw3/iptables. Ускорение потоков, мостовая фильтрация и некоторые сочетания HomeProxy TUN имеют ограничения.
- Pro управляет только явно выбранными локальными портами служб VPS. SSH настраивается отдельно; остальные порты остаются под управлением существующего межсетевого экрана.

Проведены функциональные проверки установки, обновления, интерфейса, блокировки и восстановления, IPv4/IPv6 и холодного запуска. Начните с одного клиента и проверьте реальный путь трафика, затем расширяйте область. Требования и известные ограничения см. в [совместимости](docs/COMPATIBILITY.md).
