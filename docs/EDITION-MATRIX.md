# 普通版与 Pro 的功能范围

普通版 `0.3.0-21` 与 Pro `0.3.1-5` 使用独立包和版本号。普通版提供路由器上的连接保护；Pro 增加所选 VPS 服务端口的访问管理。

| 范围 | 普通版 | Pro |
| --- | --- | --- |
| 部署位置 | OpenWrt 路由器 | 同一路由器扩展，加独立 Linux Agent；可选 Worker/Tunnel |
| 本地代理验证 | 经本机 SOCKS 的 HTTPS、可选出口 IPv4、可选 SOCKS5 UDP | 沿用普通版，可导入 VPS 出口候选 |
| 本地规则 | 明确入口、地址范围及例外；IPv4/IPv6，TCP/UDP | 沿用普通版 |
| 客户端适配 | PassWall、PassWall2、OpenClash、Nikki、HomeProxy；按具体版本和模式验证 | 沿用普通版 |
| 状态机 | 故障阈值、等待、增强监测、开机/定时保护 | 可选叠加远端健康条件及维护恢复 |
| 管理界面 | 状态、事件/检查日志、五种语言、引导、原始配置、自检与有限恢复 | 增加选定端口、认证连接、远端状态与固定操作 |
| 远端访问策略 | 无 | 每条端口规则独立选择白名单、标准防滥用或观察，支持阈值和来源配置 |
| SSH | 不管理 VPS SSH | 单独选择托管；双心跳失联后的持续或限时应急访问 |
| 远程维护 | 无 | 单独授权 VPS 重启或指定 Xray 内核操作（含受支持的 3x-ui 托管方式），不接受任意命令 |

## 独立升级

普通版与 Pro 的安装包独立编号，通过最低基础版本与 API 检查兼容。兼容时只升级 Pro 不要求重装基础包。基础层自身的安全、状态机或固件兼容修复仍需更新基础包。Pro 的专属界面和五种语言目录随 Pro 包更新；普通版本身的修复与功能变化仍需升级普通版。

Worker 与 Linux Agent 使用自己的协议/能力检查。新增远端能力可能需要更新对应配套，不能只靠路由器扩展获得服务器端实现。Worker 的 npm 项目版本不等同于 Pro 安装包版本。

Pro 自带五种语言的专属页面、策略确认和原始配置编辑器。新版 Pro 可以安装在兼容的旧普通版上。若先升级普通版，安装钩子会从设备上的旧普通版词库保留旧 Pro 仍使用的词条。安装新版 Pro 后会清理这份临时兼容词库。

## 当前边界

- 新装本地保护与 Pro 总开关默认关闭；SSH 托管、维护等另行选择。
- 监听发现只推荐候选端口，未选择端口沿用系统防火墙，不做整机默认拒绝。
- 默认控制通信及家庭地址同步配置采用 IPv4；IPv6 数据面保护不等同于 IPv6 云端管理链路已验收。
- 当前以一组路由器身份与 Agent 为中心，不承诺多 VPS 统一管理、自动密钥轮换或任意客户端兼容。
- 可信结构化遥测缺失时，不推断回落连接身份或执行精确回落带宽分类。
- 运行进程、监听端口和“运行完成”日志不能替代真实代理请求验证。

已进行安装、界面、故障恢复和兼容测试。支持条件与已知限制见[兼容范围](COMPATIBILITY.md)。

## 当前发行版的最低兼容条件

| 组件／安装格式 | 当前发布或标识 | 必须满足的条件 |
| --- | --- | --- |
| 普通版 IPK | 0.3.0-21 | LuCI、opkg、firewall4/nftables 及匹配依赖 |
| Pro IPK | 0.3.1-5 | 普通版 **≥ 0.3.0-13**，基础接口 **API 1** |
| 普通版 APK | 0.3.0-r21 | 匹配固件 SDK 的 APK、apk、LuCI、firewall4/nftables |
| Pro APK | 0.3.1-r5 | 普通版 **≥ 0.3.0-r20**，基础接口 **API 1** |
| VPS Agent 控制协议 | **v3** | Pro 校验协议、实际能力和策略确认响应，不以文件名猜测兼容性 |
| Worker npm 项目 | **0.2.0** | 转发并校验 v3 响应；项目版本不是 Agent 协议号，也不是独立兼容承诺 |

包依赖与基础 API 常量来自 [package/Makefile](../package/Makefile)。IPK 的 `-21` 与 APK 的 `-r21` 是各自包格式的修订号，不能仅改后缀互换。最低依赖表示允许安装的下限，不表示该历史版本已包含此后全部安全、功能和固件修复。

Agent 当前没有独立、完整的语义版本发布线；请使用[当前 Release](https://github.com/beezcheyenna/Proxy-Guard/releases/tag/v0.3.0-21-pro-0.3.1-5)源码中的 `companion/vps` 和按需部署的 `companion/worker`，并记录部署的 tag/commit。Worker 的 `package.json` 仍是 0.2.0，不能用这个数字证明云端代码已经更新。

### 升级决策

| 变化 | 需要更新哪些组件 | 不兼容时的行为 |
| --- | --- | --- |
| 仅 Pro 界面、翻译或兼容 API 1 的本地修复 | 可以只升级 Pro；基础包已满足上表条件时无需重装 | 不满足最低包版本或基础 API 时拒绝安装／启动对应扩展 |
| 普通版独立修复，仍提供 API 1 | 可以只升级普通版 | 不能据此推定未来不同 API 主版本也兼容 |
| 新增远端端口规则、来源模式或确认事务能力 | 先更新 Agent；使用 CF 控制时同时核对并更新 Worker，再启用 Pro 中的新能力 | 缺少 `per_rule_modes`、`source_modes_v2` 或 `policy_confirmation` 等所需能力时拒绝该次应用 |
| Agent 与 Pro 协议不同，或 Worker 无法传递所需响应 | 选择同一兼容发行源码并完成端到端核验；直接 HTTPS 不需要 Worker | v3 响应或策略回读不匹配时报告失败，不把“请求已送出”当作策略已生效 |
| Pro 读取 VPS 出口候选 | Agent 和控制链路须支持出口信息 schema 1 | 不支持或响应不合法时不能采用该候选，不自动关闭普通版连通性检查 |

这里的“独立升级”指**兼容接口范围内不要求同步升级基础包**，不表示 Pro 可以卸掉普通版后独立运行。失败应用也不等于远端原有规则已删除；先查看策略修订、待确认状态和实际规则，救援见 [RECOVERY.md](RECOVERY.md)。
