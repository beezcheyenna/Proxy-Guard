# Восстановление

[English](RECOVERY.en.md) · [简体中文](RECOVERY.md) · [日本語](RECOVERY.ja.md) · [Русский](RECOVERY.ru.md) · [فارسی](RECOVERY.fa.md)

**После остановки службы Proxy Guard правила межсетевого экрана могут продолжить блокировку.** Чтобы снять блокировку плагина, явно отключите защиту по инструкции ниже.

**Успешная проверка текущего прокси подтверждает доступность только для этого запроса.** Расписание, запрос API или отдельная неудачная проверка могут по-прежнему блокировать доступ.

## Как читать состояние восстановления

Панель состояния показывает текущую блокировку и результат последней завершённой проверки. Если правила ещё требуют проверки, откройте «Проверить настройки и среду выполнения». Кнопка «Проверить текущий прокси» проверяет путь через SOCKS.

При сбое соединения убедитесь, что локальный SOCKS клиента принимает подключения. После перезагрузки правил или перезапуска прокси дождитесь проверок восстановления.

Перед проверкой восстановления обеспечьте доступ к консоли или отдельный канал управления. При потере доступа после изменения дождитесь окончания срока подтверждения. По истечении срока или при перезагрузке до подтверждения возвращаются предыдущие настройки.

Если доступна консоль маршрутизатора, явно выключите защиту приведёнными ниже командами. Убедитесь, что блокировка выключена, затем проверьте доступ с защищаемого устройства.

```sh
umask 077
cp /etc/config/proxy_guard /root/proxy_guard.before-recovery &&
uci set proxy_guard.main.enabled='0' &&
uci commit proxy_guard &&
printf '%s\n' '{}' | ucode /usr/lib/proxy-guard/setup-lock.uc apply &&
/etc/init.d/proxy-guard restart &&
ubus call proxy_guard status
```

Защищается только трафик, который проходит через маршрутизатор. Сначала проверьте на одном устройстве входной интерфейс, IPv4, IPv6, DNS и управление. В одной подсети обратный трафик может пройти мимо маршрутизатора.
