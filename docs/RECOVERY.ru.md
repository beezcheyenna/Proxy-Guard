# Аварийное восстановление

[English](RECOVERY.en.md) · [简体中文](RECOVERY.md) · [日本語](RECOVERY.ja.md) · [Русский](RECOVERY.ru.md) · [فارسی](RECOVERY.fa.md)

Применимо к Standard `0.3.0-21` и Pro `0.3.1-5`. Защита роутера и политика на VPS управляются отдельно.

Отключение и тайм-аут подтверждения проверены в изолированной ВМ OpenWrt 24.10.8. Удаление на VPS проверено в ВМ Ubuntu и Alpine и ранее в тестах жизненного цикла четырёх дистрибутивов. Для штатного аварийного режима прошивки или повреждённого диска используйте соответствующую процедуру. См. [матрицу](TEST-MATRIX.ru.md).

## 1. Сохраните канал управления

- Оставьте SSH, последовательную консоль, консоль ВМ или провайдера VPS. Если управление по сети недоступно, используйте независимую консоль и штатный режим восстановления прошивки.
- После отключения защиты клиенты могут выйти в сеть напрямую. При необходимости сначала отключите их внешний доступ.
- Сохраняйте системные правила, файлы блокировок и ожидающие транзакции. Общая очистка экрана или удаление транзакции могут сорвать управление и откат.

## 2. LuCI недоступен, но есть SSH или консоль роутера

Проверьте состояние от root без изменений:

```sh
/usr/libexec/proxy-guard status
ubus list proxy_guard
nft list tables
logread -e proxy-guard
```

Отдельно диагностируйте отсутствующий объект ubus, ошибку LuCI и недоступный прокси. Сохраните ошибки и действующие ACL. После `/etc/init.d/proxy-guard stop` блокировка nftables может остаться. До перезагрузки сохраните журналы закрыто. Перед публикацией удалите чувствительные данные. Журнал в RAM обычно теряется после перезагрузки.

### Явное отключение Standard

Нужны читаемая конфигурация UCI, отдельный канал управления и согласие на возможный прямой доступ клиентов. Сделайте резервную копию:

```sh
umask 077
cp /etc/config/proxy_guard /root/proxy_guard.before-recovery
```

После проверки копии выполните:

```sh
uci set proxy_guard.main.enabled='0' &&
uci commit proxy_guard &&
printf '%s\n' '{}' | ucode /usr/lib/proxy-guard/setup-lock.uc apply &&
/etc/init.d/proxy-guard restart
```

Явное выключение регистрируется как подтверждённое, заменяет ожидающее включение и обрабатывается при перезапуске. Это защищает от повторного применения старой пробной конфигурации наблюдателем. Правка UCI или reload остановленной службы сами по себе не завершают транзакцию.

Проверьте:

```sh
uci -q get proxy_guard.main.enabled
/usr/libexec/proxy-guard status
nft list tables
```

Ожидаются `0`, `disabled` и состояние исполнения `off`. Таблица Standard `inet proxy_guard` удалена, `fw4` и остальные правила присутствуют. Фактический доступ зависит от действующих маршрутов, экрана и прокси.

При нечитаемой конфигурации восстановите `/etc/config/proxy_guard` из своей доверенной копии подходящей версии и выполните явное отключение. При повреждении программы или зависимости сохраните консоль и восстановите нужный пакет.

## 3. Срок подтверждения истёк

После успешной самопроверки роутер даёт **30 секунд на подтверждение**. Независимый наблюдатель откатывает изменение даже при закрытом браузере и обрыве связи. После подключения сравните состояние и прежнюю конфигурацию, проверьте правила, затем исправьте черновик. Сохраните `pending.json`. При сбое наблюдателя, хранилища или среды выполните явное отключение через консоль и проверьте правила.

## 4. Процесс завершился, блокировка осталась

Ядро продолжает применять правила после выхода процесса. Разрешения могут истечь. Оставив защиту, сохраните журналы и проверьте хранилище, зависимости, UCI и интерфейсы. Восстановите и перезапустите плагин. Для временного снятия используйте раздел 2. Не запускайте параллельные ручные проверки и сохраняйте файлы блокировок. До повторного включения и подтверждения проверьте одного клиента.

## 5. Pro недоступен, правила VPS остались

Остановка синхронизации прекращает продление. Динамическое разрешение домашнего IP истекает, а статические списки и правила выбранных портов могут остаться. Аварийный SSH требует предварительного включения и подтверждения и потери обоих аутентифицированных сигналов по настройке. Системный экран, аутентификация SSH и группы провайдера сохраняются. При неизвестном результате прочтите удалённое состояние. Сохраняйте ревизии и ID операций. Управление на общем порту прокси тоже может попасть под правила, поэтому держите отдельную консоль.

При доступном управлении используйте удаление и подтверждение Pro. Проверьте правила на VPS перед остановкой синхронизации.

### Удаление правил компонента из консоли VPS

Отключите автоматическую синхронизацию на роутере на время восстановления. Сохраните консоль и системный экран. Закрыто сохраните действующий `/etc/proxy-guard-access/agent.json`, ключи, сертификаты и постоянное состояние. Перейдите в `companion/vps` доверенных исходников установленной версии и выберите команды для своей системы.

Ubuntu, Debian, Rocky Linux:

```sh
sudo sh ./uninstall.sh --remove
sudo systemctl status proxy-guard-access proxy-guard-access-policy --no-pager
sudo nft list tables
```

Alpine Linux от root:

```sh
sh ./uninstall.sh --remove
rc-service proxy-guard-access status
rc-service proxy-guard-access-policy status
nft list tables
```

После удаления запрос состояния может вернуть отсутствие службы и ненулевой код. При ошибке самого удаления сохраните вывод и остановитесь. Удаляются службы компонента, их зависимости запуска и собственные правила. Конфигурация, ключи и программы сохраняются, NAT, FORWARD и чужие правила остаются. Проверьте управление и сервисные порты. `pg_vps_access` — имя по умолчанию, сверяйтесь с действующей конфигурацией. При её повреждении сначала установите принадлежность таблиц.

Переустановка может восстановить сохранённую политику. Сначала проверьте конфигурацию и состояние, затем управление, динамические разрешения, режимы портов и SSH. Используйте состояние своего экземпляра и сохраняйте рост ревизии.

## 6. Проверка после восстановления

С одного защищаемого клиента проверьте LAN, DNS, управление, IPv4/IPv6, новые и существующие соединения, сбой и восстановление. Для проверки защиты при загрузке сохраните отдельное управление и перезагрузите **роутер с Proxy Guard**.
