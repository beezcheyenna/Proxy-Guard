Приветствуются воспроизводимые отчёты, результаты совместимости, исправления документации и небольшие тематические pull request.

- [Сообщить об ошибке](https://github.com/beezcheyenna/Proxy-Guard/issues/new?template=bug_report.yml)
- [Результат совместимости](https://github.com/beezcheyenna/Proxy-Guard/issues/new?template=compatibility.yml)
- [Предложить функцию](https://github.com/beezcheyenna/Proxy-Guard/issues/new?template=feature_request.yml)
- [Отзыв о документации](https://github.com/beezcheyenna/Proxy-Guard/issues/new?template=documentation.yml)

Сообщайте об уязвимостях приватно по правилам политики безопасности. Для обычных ошибок используйте обезличенные публичные отчёты. [Политика безопасности](SECURITY.ru.md)

## Перед изменением поведения

1. Опишите условие, ожидаемое и фактическое поведение. Используйте адреса документации и минимальную обезличенную схему.
2. Укажите прошивку, ядро, архитектуру, формат пакета, установленную версию Proxy Guard, реально запущенное прокси-ядро и режим. Различайте метаданные пакета и процесс.
3. Работайте в разрешённой изолированной среде. Сценарии со службами, маршрутами и экраном запускайте в одноразовой ВМ.
4. Ограничьте изменения задачей. Сохраняйте ACL, проверку сертификатов и не связанные с задачей NAT, DNS и сеть.

См. [инструкцию по сборке](BUILDING.ru.md) и [матрицу тестирования](TEST-MATRIX.ru.md). Установка и путь пакетов проверяются отдельно.

## Документация и переводы

Главная страница на английском, затем упрощённый китайский, японский, русский и персидский. При изменении поведения обновляйте связанные страницы и ссылки во всех пяти языках. Журнал изменений английский и сохраняет старые URL. Сохраняйте оригиналы лицензий и уведомлений.

Из корня репозитория запустите проверки.

```sh
python3 tools/check_docs.py
python3 -m unittest discover -s tools/tests -p 'test_check_docs.py'
```

Проверяются наличие переводов, язык ссылок, якоря, версии и имена пакетов. Смысл переводов проверяйте при чтении. Для PR проверки офлайн, для основной ветки и выпуска также выполняется сравнение с последним стабильным GitHub Release. После заблаговременной смены версии повторите проверку при выпуске.

## Pull request и подтверждения

Опишите проблему, изменение, проверку и оставшиеся границы. Для совместимости запишите версии и дату, различайте моки, изолированную ВМ и рабочую среду, сохраняйте исходный сбой. Не добавляйте собранные пакеты, приватные журналы и постороннее форматирование. См. [лицензирование](LICENSING.ru.md).
