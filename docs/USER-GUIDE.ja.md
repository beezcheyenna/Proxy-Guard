LuCI と firewall4/nftables を使うルーターに Proxy Guard をインストールします。パッケージ形式はファームウェアに合わせてください。

## 初回設定

「サービス → プロキシ接続保護」でウィザードを開き、入口インターフェース、IPv4 と IPv6 の範囲、ローカル例外、SOCKS ポートを確認します。最初は監視専用で試します。保存して適用すると自己検査が実行され、確認時間は 30 秒です。検査に失敗した場合や確認しなかった場合は元の設定に戻ります。

LuCI、firewall4、nftables が必要です。OpenWrt 24 は IPK、25.12 は APK を使います。iStoreOS と ImmortalWrt は各ファームウェアのパッケージ管理とカーネル依存関係に合わせてください。

保護の対象は実際にルーターを経由する通信です。範囲を広げる前に一台で入口、IPv4 と IPv6、DNS、管理経路を確認します。同一サブネットでは戻りの通信がルーターを迂回する場合があります。

ルールの確認が済むまで「この設定を維持」ボタンは無効です。元のカウントダウンは続きます。時間切れになると、ページを閉じていてもルーターが以前の設定に戻します。

## 動作モード

- **監視のみ**は障害を記録し、インターネット通信を許可したままにします。
- **保護**は障害を確認した後、対象範囲のインターネット通信を遮断します。起動中も遮断するには起動時の保護プリセットを選びます。
- **スケジュール保護**は毎日または指定曜日に設定できます。UTC オフセットは固定で、既定値は UTC+00:00 です。

サービスとログの監視でクライアントの再起動を検知すると、復旧の確認が始まります。ウォッチドッグは Proxy Guard 自身を監視します。UDP 経路を個別に確認する場合は、UDP プロキシ経路の検証を有効にしてください。

## 現在のプロキシをテスト

既定の公式 HTTPS はローカル SOCKS 経由で固定アドレスへ接続します。外部 HTTPS には独立した間隔としきい値があります。出口 IPv4 の照合は初期状態では無効で、有効にすると既定で公式応答のアドレスを使います。外部 IP サービスは主アドレスがタイムアウトした場合だけ予備を試します。

「現在のプロキシをテスト」は保存前のフォームの設定で SOCKS 経由の接続を試し、結果、応答時間、取得できた出口 IPv4 を表示します。保護設定は「保存して適用」で反映されます。

設定フォームの下にある「設定と診断」から、設定と動作環境の確認、現在のプロキシのテスト、機密情報を除いたレポートの表示ができます。設定ウィザードの再実行、UCI 設定の直接編集、前回確定した設定の読み込み、初期設定へのリセットもここから行えます。

「設定と診断」で「現在のプロキシをテスト」を開き、ダイアログの「詳細診断を実行」を選ぶと、ルーターがローカル SOCKS 経由で `/f` に一度接続し、応答の `X-PGHB-*` ヘッダーを表示します。

## 検査と復旧の設定

公式 HTTPS の既定値は検査間隔 3 秒、タイムアウト 2 秒です。連続 2 回の失敗で障害、連続 2 回の成功で復旧と判定します。外部 HTTPS の既定値は間隔 10 秒、各検査先のタイムアウト 4 秒です。連続 3 回の失敗で障害、連続 2 回の成功で復旧と判定します。通常は 1 回の検査で少なくとも一つの検査先に成功する必要があります。

クライアント監視を有効にすると、設定したサービスの中断やログで検知した中断が遮断を開始できます。設定した条件を満たすと復旧確認が始まります。通信再開後の重点監視では検査間隔を短くでき、その間の再障害で通信が再び遮断されることがあります。

スケジュールによる遮断には総スイッチと保護モードが必要です。スケジュール、API による遮断、検査失敗が重なった場合は、すべての遮断理由が解消した時点で通信を再開します。

## 遮断と復旧

状態欄には連続失敗回数と有効な遮断理由が表示されます。しきい値未満の失敗では通信が継続する場合があります。定時保護、API による一時遮断、接続障害は同時に起こり得ます。

ローカル API は既定で無効です。有効にすると、LuCI に表示される UUID で呼び出せます。[ローカル API の使い方](USAGE.ja.md#local-api)

「イベントログ」では、最近の接続確認の詳細と復旧履歴を展開できます。「ログと復旧履歴を消去」は、これら三つの記録をまとめて消去します。進行中の復旧状態は引き続き表示され、消去操作はイベントログに記録されます。
