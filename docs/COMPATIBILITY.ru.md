# Совместимость и ограничения

[English](COMPATIBILITY.en.md) · [简体中文](COMPATIBILITY.md) · [日本語](COMPATIBILITY.ja.md) · [Русский](COMPATIBILITY.ru.md) · [فارسی](COMPATIBILITY.fa.md)

Требуются LuCI, firewall4 и nftables. Для OpenWrt 24 используется IPK, для OpenWrt 25.12 — APK. Для iStoreOS и ImmortalWrt сверяйте пакетный менеджер и зависимости ядра своей прошивки.

Защищается только трафик, который проходит через маршрутизатор. Сначала проверьте на одном устройстве входной интерфейс, IPv4, IPv6, DNS и управление. В одной подсети обратный трафик может пройти мимо маршрутизатора.

Официальная проверка HTTPS по умолчанию обращается к фиксированному адресу через локальный SOCKS. У сторонней проверки свои интервалы и пороги. Проверка исходящего IPv4 изначально выключена и после включения по умолчанию использует адрес из официального ответа. Резервный сторонний IP-сервис опрашивается только при тайм-ауте основного.

Выберите поддерживаемый режим клиента и проверьте пути IPv4 и IPv6 для защищаемых устройств. В [матрице тестирования](TEST-MATRIX.ru.md) перечислены сочетания прошивок, прокси-клиентов и режимов пересылки, а также результаты целевых проверок пакетов 1.0.

| Прокси-клиент | Режимы перенаправления | Что проверить |
| --- | --- | --- |
| PassWall | TCP REDIRECT + UDP TPROXY или TCP/UDP TPROXY | Включите IPv6 TPROXY в клиенте, если IPv6 должен идти через прокси. Маршрутизируемый IPv6-трафик проверяйте отдельно. |
| PassWall2 | TCP/UDP TPROXY | Проверьте, какой локальный SOCKS принимает соединения. Другие режимы проверяйте в своей конфигурации. |
| OpenClash | REDIRECT + TPROXY или TUN | Сохраните аутентификацию SOCKS. Для передачи UDP по IPv6 через прокси включите эту возможность в клиенте. |
| Nikki | REDIRECT + TPROXY или TUN | Сохраните данные аутентификации SOCKS и проверьте обе версии IP в выбранном режиме. |
| HomeProxy | REDIRECT + TPROXY или system TUN | Проверьте IPv6 UDP на установленных версиях sing-box и прошивки. |

Результат также зависит от прокси-ядра. NaiveProxy не передаёт UDP. Прослушивание только IPv4 само по себе не подтверждает проксирование IPv6. При проблемах с Xray SOCKS5 UDP проверьте ядро и режим перенаправления в контрольной среде с отключённой защитой.

Если UDP по IPv6 должен идти через прокси, проверьте именно этот путь. Успешная проверка TCP или подключение к SOCKS подтверждает только соответствующий путь.

Приложение LuCI доступно на английском, упрощённом китайском, японском, русском и персидском языках. Тема и другие приложения используют свои переводы. [Совместимость журналов](LOG_COMPATIBILITY.ru.md)

## Требования режима защиты

Подтверждение блокируется, если в UCI включён программный или аппаратный offload, осталась активная таблица nft flowtable, `bridge-nf-call-iptables` или `bridge-nf-call-ip6tables` передаёт чисто коммутируемый трафик в IP-фильтр, либо невозможно проверить вход, ядро, состояние моста или установленную политику. Проверьте настройки на устройстве.

Аппаратное ускорение производителя и обход через коммутатор проверяйте на устройстве. В проверенных схемах без NAT ответы возвращались через тот же маршрутизатор. Шлюз в той же подсети может видеть только исходящий путь. Устройства с другим шлюзом, подключённые только через коммутатор, должны сохранять доступ. Проверьте LAN между подсетями, VPN, контейнеры, несколько мостов и маршрут IPv6 по умолчанию.
