# Совместимость и ограничения

Точные версии прошивок, ОС, ядер и клиентов, архитектуры, даты и незавершённые проверки приведены в [матрице](TEST-MATRIX.ru.md). Проверялись установка, обновление, LuCI/RPC, блокировка при сбое, восстановление и холодный запуск. Метка `all` означает пакет скриптов.

## Маршрутизаторы и клиенты

Нужны LuCI и firewall4/nftables. Для opkg используйте IPK, для apk — APK из соответствующего SDK. Берите зависимости и модули ядра из источников конкретной прошивки. Совпадение версии ядра и метки ABI не делает модули разных поставщиков взаимозаменяемыми.

| Клиент | Проверенный режим или сценарий | Условия |
| --- | --- | --- |
| PassWall / Xray, sing-box | TCP REDIRECT + UDP TPROXY, TCP/UDP TPROXY | Для проксирования IPv6 включите IPv6 TPROXY в клиенте. В режиме REDIRECT проверялся защищаемый маршрутизируемый трафик IPv6. |
| PassWall2 / Xray, sing-box | TPROXY | REDIRECT и другие комбинации проверяйте отдельно. |
| OpenClash / Mihomo | REDIRECT + TPROXY, TUN | Сохраняйте аутентификацию SOCKS при выключенном наблюдении за службами. Проксирование IPv6 UDP включается явно. Проверены TPROXY и TUN. При выключенной настройке IPv6 UDP может идти напрямую. |
| Nikki / Mihomo | REDIRECT + TPROXY, TUN | Сохраните аутентификацию SOCKS и проверьте выбранный режим. |
| HomeProxy / sing-box | REDIRECT + TPROXY, system TUN | TCP и UDP для IPv4/IPv6 повторно проверены на официальном sing-box 1.14.4 без старого патча sing-tun. |
| PassWall / Hysteria2, Shadowsocks-Rust, NaiveProxy | Распознавание нативных слушателей, блокировка и восстановление | Проверены Hysteria2, Shadowsocks-Rust, а также NaiveProxy HTTPS и QUIC. NaiveProxy не пересылает UDP. Проверки его IPv6 относились к маршрутизируемому трафику. Обычный IPv4-сокет Shadowsocks-Rust не подтверждает проксирование IPv6. |
| PassWall / sing-box ShadowTLS v3 → ShadowTLS | Проксирование TCP, блокировка и восстановление | TLS проверялся с действующим закрытым тестовым CA. UDP проверялся на отдельном защищаемом маршруте. |
| ShadowTLS | Процесс и слушатели нативного клиента | Штатный клиент не доверяет частному CA лаборатории. Сквозная проверка остаётся открытой. |

В лаборатории без Proxy Guard параллельные ассоциации SOCKS5 UDP через Xray 26.11.9 повторно занимали временные UDP-порты и завершались по тайм-ауту. Стабильная пересылка UDP для этой комбинации не подтверждена. При диагностике сохраняйте UDP-проверку. Другие транспорты Xray требуют отдельных результатов.

Сверяйте версии интерфейса, пакета и запущенного ядра отдельно. Установку ядра выполняет прокси-клиент. Проверялись OpenWrt, ImmortalWrt и iStoreOS серий 24 и 25.12. Выбирайте соответствующий формат пакета. Прошивки только с fw3/iptables не поддерживаются. Для других прошивок, ядер и архитектур проверяйте реальный путь.

Проверки трафика охватывали новые и существующие TCP/UDP-соединения IPv4/IPv6, повторный сбой при усиленном наблюдении, сохранение DNS, управления и доступа самого маршрутизатора.

## Языки и темы LuCI

Страницы Standard и Pro доступны на упрощённом китайском, английском, японском, русском и персидском. При Argon на iStoreOS 24 наблюдалось, что инициализация PassWall2 26.11.3-r1 переключает автоматический язык LuCI на английский. Укажите язык в системных настройках LuCI явно. Меню прошивки и другие плагины используют собственные переводы.

## VPS Agent

На Ubuntu, Debian, Rocky Linux и Alpine Linux проверялись установка, сохранение настроек, аутентифицированный API, TCP/UDP по IPv4/IPv6 и поддерживаемые операции обслуживания. Сверьте версии 3x-ui и Xray и выберите подходящий адаптер.

Требуются Python 3.10+, nftables, динамические наборы, ограничение скорости, connlimit и соответствующие модули ядра. Перед установкой запустите `--check-kernel`. Поддерживаются systemd и Alpine OpenRC. Agent работает с выбранными локальными портами INPUT и частью соответствующих ответов OUTPUT для подтверждённого ограничения fallback. NAT, FORWARD, опубликованные Docker-порты, другие пространства имён и внешние группы безопасности находятся вне этой области.

Автообнаружение предлагает порты. Выберите нужные и отдельно разрешите управление SSH и обслуживание. Настройки SNI/REALITY сами по себе не подтверждают аутентификацию. Для точного ограничения fallback нужны свежие доверенные структурированные данные.

## Требования режима защиты

Подтверждение блокируется, если в UCI включён программный или аппаратный offload, осталась активная таблица nft flowtable, `bridge-nf-call-iptables` или `bridge-nf-call-ip6tables` передаёт чисто коммутируемый трафик в IP-фильтр, либо невозможно проверить вход, ядро, состояние моста или установленную политику. Проверьте настройки на устройстве.

Аппаратное ускорение производителя и обход через коммутатор проверяйте на устройстве. В проверенных схемах без NAT ответы возвращались через тот же маршрутизатор. Шлюз в той же подсети может видеть только исходящий путь. Устройства с другим шлюзом, подключённые только через коммутатор, должны сохранять доступ. Проверьте LAN между подсетями, VPN, контейнеры, несколько мостов и маршрут IPv6 по умолчанию.

## Границы обнаружения и восстановления

HTTPS, необязательное сравнение выходного IPv4, проверка служб и необязательный IPv4 DNS UDP проверяют разные пути. Успех относится к проверенному пути. Сравнение IPv4 выключено при новой установке, обновление сохраняет выбор.

Службы опрашиваются примерно раз в секунду, журнал читается частями с интервалом 1–10 секунд по настройке. Краткий сбой может попасть между опросами. Распознавание опирается на проверенные сообщения, время и этапы запуска. При неверных часах восстановление по журналу невозможно. Расписание использует фиксированное смещение UTC. См. [совместимость журналов](LOG_COMPATIBILITY.ru.md).

procd запускает завершившиеся процессы. Сторож плагина ограниченное число раз перезапускает плагин при сбое heartbeat. Обычный сбой прокси обрабатывает защита. После длительного отключения при включении даётся новое время на запуск. При исчерпании попыток защита остаётся включённой, интерфейс предлагает диагностику. Восстановление зависит от файловой системы, ядра, планировщика, procd и сторожа. Журнал плагина хранится в RAM, системный журнал следует настройкам прошивки.

## Проверка при развёртывании

Проверьте физические интерфейсы, ускорение, асимметричные маршруты, длительную работу и новые версии клиента в своей сети. При смене публичного домашнего IP проверьте новый срок доступа и истечение старого. Для Cloudflare также проверьте привязку и соединение. Начните с наблюдения за одним устройством. Проверьте LAN, DNS, управление, другой шлюз, IPv4/IPv6, установленные соединения и восстановление. Перед проверкой загрузки сохраните канал управления или консоль.
