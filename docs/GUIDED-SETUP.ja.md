# 設定ウィザードと確認・ロールバック

[English](GUIDED-SETUP.en.md) · [简体中文](GUIDED-SETUP.md) · [日本語](GUIDED-SETUP.ja.md) · [Русский](GUIDED-SETUP.ru.md) · [فارسی](GUIDED-SETUP.fa.md)

新規インストール後、最初にページを開くとウィザードが表示されます。閉じるか後で設定を選ぶと保護は無効のままです。設定画面から再開できます。

1. 既存の LAN レイヤー 3 入口を選びます。候補は netifd のアドレスと LAN ファイアウォールゾーンから取得します。LAN マスカレードも認識し、NAT は維持します。
2. 監視のみ、障害時保護、起動時保護から選びます。クライアント、SOCKS ポート、サービス監視、スケジュールを確認します。入力は下書きです。
3. 送信元の範囲、LAN の例外、プロキシ入口、DNS リダイレクトポートを確認します。別サブネットや特殊なポートは必要に応じて追記します。
4. 概要を確認し、**保存して適用**を押します。終了、戻る、プリセット復元ではまだ適用しません。

IPv6 は別に選びます。検出したプレフィックス、手入力、選択した入口の全送信元（`::/0`）、または IPv6 を照合しない設定です。一時アドレスとプレフィックスの変更を考慮します。除外時は `ipv6_protect=0` を保存し、UCI が空リストを省略しても範囲を広げません。システムの IPv6 は有効なままです。検出した LAN IPv6 プレフィックスは例外に入ります。公開範囲や未確認の上流ポートは LAN の例外に入れないでください。

## プリセットの選択

| プリセット | 用途 | 確認点 |
| --- | --- | --- |
| 監視のみ | 初回の入口・クライアント認識と検査の確認 | 外部通信は遮断しません。遮断を有効にする前に実経路を確認します。 |
| 障害時保護 | 入口、範囲、例外を確認済み | クライアント、SOCKS、有効な監視項目、管理経路を確認します。 |
| 起動時保護 | 障害時保護を検証済みで起動中も通信を保留する場合 | 保護スイッチ、保護モード、サービス監視、起動時保護を有効にし、ルーター再起動を別に検証します。 |

複数 LAN、サブネット間通信、動的 IPv6 プレフィックス、VPN、コンテナーは個別に確認します。ウィザードは既存のインターフェース、ゲートウェイ、NAT、DNS、プロキシ分岐を使います。スイッチ専用の入口ではパケットが実際にこのルーターを通るか確かめます。

スケジュールは別途設定します。異なる開始・終了時刻、曜日、固定 UTC オフセットを入力し、適用前に概要を確認します。既定プリセットへの復元は下書きを準備する操作です。

## ローカル確認とロールバック

バックエンドは構成とカーネル機能を検証し、検査プロセスと実際のルールを確認します。自己診断は約 120 秒まで待ちます。成功後、ルーター側で 30 秒の確認を開始します。適用したセッションだけが確認または取り消せます。他のセッションはトークンの取得や保留中の有効化の上書きができません。

ブラウザーを再読み込み・終了しても、接続が切れても、時計を変えてもタイマーは進みます。確認前の再起動ではロールバックします。トランザクション状態が破損した場合は別のバックアップから復旧を試みます。成功の判断には実際のルールも確認します。

プロキシが停止している場合、保護モードは遮断を維持して復旧を待ちます。構成やルールの不備なら、初回有効化は無効へ、既存の保護は最後に確認した構成へ戻ります。明示的な無効化を保留中の有効化より優先します。

前回確認した設定の読み込みと既定値からの再設定はフォームだけを変更します。戻ると選択内容を保持し、リセットで未保存の入力と下書きを破棄します。更新時は設定を保持し、初回ウィザードを強制しません。

## Pro の想定出口

Pro の認証済み接続を保存します。基本設定で出口照合を有効にし、取得元を選んで VPS のアドレスを読み込みます。公開インターフェース、パネル設定の候補、任意の既定経路測定が使えます。複数候補は自分で選ぶか、把握しているアドレスを入力します。

パネル由来の候補は Agent で明示した信頼できるローカル Xray 設定から読みます。REALITY の宛先やリモートサーバーと出口は区別し、秘密鍵は出力しません。他のパネル API や多段経路は個別に検証してください。測定は既定で無効で、固定の測定先、タイムアウト、最小間隔を使います。状態照会は既存の測定を使います。

取り込みは下書きに反映されます。NAT、WARP、複数出口、多段プロキシではインターフェースやパネルのアドレスと実出口が異なる場合があります。SOCKS 経路を独立して検証します。検出した未知の IP を自動で信頼しません。[出口 API](VPS-EGRESS-INFO.ja.md) を参照してください。

## 実際の経路を確認する

端末 1 台で新規・既存の IPv4/IPv6 TCP/UDP 通信を確認します。障害時は外部を遮断し、LAN、DNS、管理、ルーター自身は通信できることを確認します。別ゲートウェイの端末も試します。このルーターを迂回する戻り経路やスイッチング通信は対象外です。自己診断で見るのは構成・プロセス・ルールです。ブラウザー、機器固有の高速化、配備構成は別に検証します。

## Pro のリモートポリシー確認

既定では **保存して適用**で VPS Agent が試行適用します。VPS で適用後、操作したログインセッションは既定 60 秒以内に確認します。30～300 秒に設定できます。ページを閉じても進みます。期限切れでは以前のポート・SSH ポリシーに戻し、増加するリビジョンと現在の認証済み IP を保持します。期限切れリースは復元しません。プロセス再起動は残り時間を維持し、VPS 起動では未確認ポリシーを先に復元します。期限の確認は通常約 5 秒ごとです。Agent の停止時はサービス監視による復旧が必要です。カーネルやストレージ障害では遅れる場合があります。

結果が確定するまでルーターは非公開スナップショットを保持します。確認を送信して応答を失った場合はリモート状態を照会します。別セッションが設定や秘密情報を変更した場合は競合を表示します。新機能には対応する Agent、Cloudflare では Worker も必要です。権限不足の旧セッションは再ログインします。確認を無効化した場合や旧版・root の CLI 同期は即時適用です。別の管理経路を確保してください。

**同期停止**はハートビートと更新を停止します。ルール削除は削除準備、下書き確認、保存と適用、プロキシポート・SSH のポリシー削除の確認を行ってから同期を停止します。プロキシと SSH サービスは稼働し、システムファイアウォールは引き続き適用されます。中断後は結果不明や競合をリモート状態で照合します。[障害復旧](RECOVERY.ja.md) を参照してください。
