# Cloudflare Worker для Pro

[English](CLOUDFLARE-WORKER.en.md) · [简体中文](CLOUDFLARE-WORKER.md) · [日本語](CLOUDFLARE-WORKER.ja.md) · [Русский](CLOUDFLARE-WORKER.ru.md) · [فارسی](CLOUDFLARE-WORKER.fa.md)

Worker аутентифицирует устройства, определяет публичный IP домашней сети и пересылает политики по протоколу Agent v3. Нужны совместимые версии Pro и VPS Agent. Каждый Worker обслуживает один идентификатор устройства и фиксированную привязку `VPS_API`.

## Зависимости и локальные проверки

Используйте Node.js 22 или новее. В `package-lock.json` закреплены Wrangler 4.156.0 и Miniflare 5.20261023.3-beta. При развёртывании используется установленный Wrangler. После изменения инструментов или даты совместимости в `wrangler.jsonc` (сейчас `2026-11-01`) проверьте среду выполнения заново.

В выделенной тестовой среде Linux перейдите в `companion/worker` и выполните:

```sh
npm ci
npm test
npm run test:persistence
npm run check:bundle
```

При первом запуске `npm ci` обычно загружает зависимости. После установки локальные тесты выполняются без обращения к Cloudflare. Для развёртывания и облачной проверки нужны разрешённые облачные ресурсы.

Реальные проверки nftables идут в частных сетевых пространствах имён одноразовой ВМ. `test/run_checks.sh` и `test/run_final.sh` требуют соответствующей оснастки и рабочего каталога. Тесты обслуживания записывают действия без реальной перезагрузки. `kernel_lease_test.py` проверяет, что разрешение ядра на 120 секунд исчезает через 125 секунд и отсутствует после холодного запуска.

## Развёртывание

Отдельно установите и проверьте [Linux Agent](LINUX-AGENT-INSTALL.ru.md). Запустите `cloudflared` для выделенного Tunnel на том же VPS. VPC Service направляется на локальный сокет Agent, обычно HTTP `127.0.0.1:8788`. Укажите ID этого Service в `VPS_API`.

- `DEVICE_ID` должен совпадать с настройкой Agent.
- Для связи устройства с Worker используйте случайный `DEVICE_TOKEN`, для связи Worker с Agent — отдельный `AGENT_SECRET`.
- Оба секрета содержат 32–256 букв, цифр, подчёркиваний или дефисов. Заполнители `REPLACE_` отклоняются.
- `.dev.vars.example` перечисляет необходимые секреты. Храните реальные значения в закрытом хранилище. Не добавляйте в репозиторий `.dev.vars`, `.env` и файлы секретов.
- Укажите ID Service в `wrangler.jsonc`. Задайте секреты заранее или передайте тестовые значения через `npm run deploy -- --secrets-file /path/to/private-secrets.json`. Поля JSON — `DEVICE_TOKEN` и `AGENT_SECRET`. В примере нет действующего ID ресурса.

Назначение определяется хостом и портом VPC Service. Другой адрес в URL fetch не меняет назначение. Проверьте настройки Service и привязку в Cloudflare.

## API и данные

Укажите User-Agent приложения, например `ProxyGuardPro/0.2.0`. При ошибке Cloudflare `1010` проверьте идентификатор клиента и политику безопасности учётной записи.

Для всех маршрутов нужны HTTPS и Bearer-токен устройства. Параметры запроса не принимаются.

| Маршрут | Поведение |
| --- | --- |
| `/v1/observe` | Возвращает публичный IP, видимый Cloudflare. Отклоняет источники подзапросов Worker и зарезервированные адреса. Разрешение Agent не продлевается. |
| `/v1/sync` | Требует только что наблюдавшийся IP. Worker подписывает точные байты JSON отдельным ключом HMAC-SHA256 и создаёт новый ID запроса. Agent проверяет подпись, срок, повтор и ревизию. Одна ревизия продлевает лишь ту же политику. IPv4 и IPv6 продлеваются отдельно на 120–86400 секунд. После остановки синхронизации срок разрешений истекает. |
| `/v1/status` | Возвращает нужные Pro сведения о политике, сроках, состоянии и обслуживании. Всегда запрашивает `include_analysis=false`. Исключает адреса управления, список сокетов, события, подробности источников аутентификации и неизвестные поля. Срок не продлевается. |
| `/v1/command` | Принимает `restart_xray` или `reboot_vps` с постоянным ID операции, ревизией политики и сроком 1–60 секунд. Каждое действие отдельно разрешается на Agent. При неизвестном результате используйте тот же ID для запроса или повтора с дедупликацией. Worker возвращает фиксированные коды отказа и ограничивает поток ответа до 32768 байт. |

Agent рассчитывает `expires_at` по оставшемуся монотонному времени после применения правил. Задержка применения не увеличивает отображаемый срок.

## Версии и состав развёртывания

У [проекта инструментов Worker](../companion/worker/package.json) своя версия npm `0.2.0`. У пакета Pro отдельная ревизия. Требования к Node.js и инструментам указаны в манифесте и файле фиксации зависимостей. VPS, Agent, Tunnel и VPC Service настраиваются отдельно.

## Кандидаты выходного адреса только для чтения

`POST /v1/egress-info` использует Bearer-токен устройства и непустой JSON `{ "device_id": "home" }`. Запрос передаётся только на одноимённый HMAC-маршрут фиксированного `VPS_API`. Допустимые источники — `interface`, `panel` и `measured`. Отсутствие, устаревание и неоднозначность отмечаются предупреждениями. Ожидаемый адрес выбирается явно. Измерение по умолчанию выключено. Запрос не продлевает разрешения, не записывает сигналы управления и не подтверждает политику. Старый Agent возвращает 501 `egress_info_unsupported`. Протокол, фиксированная цель измерения и интеграция описаны в [API Agent](VPS-EGRESS-INFO.ru.md).
