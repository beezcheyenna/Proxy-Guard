# 安装与使用

本文介绍普通版 `0.3.0-21` 与 Pro `0.3.1-5` 的安装、配置和维护。安装前先阅读[兼容范围](COMPATIBILITY.md)及[精确测试矩阵](TEST-MATRIX.md)；日常设置见[使用指南](USER-GUIDE.md)。

## 安装前校验下载文件

从[同一正式 Release](https://github.com/beezcheyenna/Proxy-Guard/releases/tag/v0.3.0-21-pro-0.3.1-5)下载目标包和其附件 `SHA256SUMS`，放在同一目录。文件名、普通版／Pro、IPK／APK 和版本都要对应；不要混用另一 Release 的清单。

在有 `sha256sum` 的 Linux 或 OpenWrt 上，仅核验一个已下载的包：

```sh
# IPK 示例；APK 可将下一行换为 luci-app-proxy-guard-0.3.0-r21.apk
PG_PACKAGE=luci-app-proxy-guard_0.3.0-21_all.ipk
awk -v f="$PG_PACKAGE" '$2 == f { print; n++ } END { if (n != 1) exit 1 }' SHA256SUMS > SHA256SUMS.selected &&
sha256sum -c SHA256SUMS.selected
```

必须看到所选文件的 `OK` 且命令退出成功；缺少清单条目、重复条目、文件不存在或校验失败都应停止安装。若清单中的文件已全部下载，也可直接执行 `sha256sum -c SHA256SUMS`；仅下载部分附件时，其余缺失文件会报错，不能把整份清单报错解释为当前包已通过。

macOS 可执行 `shasum -a 256 文件名`，把输出的完整 64 位摘要与同一 Release 的对应行逐字核对；这只计算摘要，不会自动取得可信发布者身份。

**SHA256 验证的是文件与清单的一致性。** 若攻击者同时替换了包和清单，校验仍可能通过。当前 Release 的 `SHA256SUMS` 不是独立数字签名；不要把它描述为发布者身份认证。请从正确仓库的 HTTPS Release 入口取得文件；如未来提供签名或证明，仍须核验独立可信的签名身份。

## 安装、升级和卸载

先按固件选择包格式：使用 opkg 的 24 系列安装 IPK，使用 apk 的 25.12 系列安装 APK。不要把 IPK 改后缀当作 APK，也不要混用两个包管理器。可以通过 LuCI 上传对应文件，或上传后在路由器执行。

**opkg / IPK：**

```sh
opkg install /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk
```

**apk / APK：**

```sh
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-0.3.0-r21.apk
```

这里的 `--allow-untrusted` 用于手工安装已核对来源与 SHA256 的本地包，不会跳过依赖检查。`--no-network` 要求所需依赖已安装；缺少依赖时，先从固件匹配的软件源准备依赖，再安装本地包。

Pro 是普通版的扩展，需要已安装兼容的基础包，但不要求两个版本号一致。首次安装可以在同一次事务中安装两个包：

```sh
opkg install /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk /tmp/luci-app-proxy-guard-pro_0.3.1-5_all.ipk
```

APK 固件对应命令：

```sh
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-0.3.0-r21.apk /tmp/luci-app-proxy-guard-pro-0.3.1-r5.apk
```

以后只升级 Pro 时，上传并安装与固件格式匹配的新 Pro 包即可，不需重复安装或更新普通版。Pro 通过最低基础版本与稳定基础接口检查兼容性；缺少接口或接口不兼容时会拒绝安装并说明原因。普通版也可独立发布修复，接口兼容时不要求升级 Pro；安全修复和固件兼容修复仍应正常维护。

普通版只需路由器端，不依赖 Linux Agent 或 Cloudflare。Pro 的远程控制与家庭 IP 授权需要另装 VPS Agent，控制链路可选直接 HTTPS，或 Cloudflare Worker 与 Tunnel/VPC；只装扩展包不会自动创建这些资源。Linux 安装步骤见[Linux Agent 安装](LINUX-AGENT-INSTALL.md)。

Pro 从 0.3.1-2 起会在安装和启动时把旧 UCI 中的 `device_token`、`path_token` 迁入仅 root 可读的密钥文件，包括插件关闭时。新增密钥应通过界面的暂存与应用流程提交。若早期明文配置曾向不可信账号开放读取权限，应在设备和配套服务上同步轮换密钥。

所需依赖必须在目标系统及其匹配的软件源中可用，基础环境见[兼容范围](COMPATIBILITY.md)。离线安装还需要事先准备匹配的依赖包；不要混用其他固件的内核模块或软件源。

基础包声明依赖 `luci-base`、`lua`、`libuci-lua`、`luci-lib-jsonc`、`luci-lib-nixio`、`rpcd-mod-file`、`firewall4`、`curl`、`ca-bundle`、`ucode`、`ucode-mod-fs` 和 `ucode-mod-uci`。包管理器会处理它们各自的依赖。不需要额外的独立 `flock` 包；不要用 `--force-depends` 绕过缺失依赖。

若下载的是**同一版本号的重新构建包**，普通的 `opkg install` 可能不会替换文件。先确认来源和 SHA256、备份配置，再仅对确实要替换的包使用：

```sh
opkg install --force-reinstall /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk
# 仅当需要替换已安装的 Pro 时执行下一行
opkg install --force-reinstall /tmp/luci-app-proxy-guard-pro_0.3.1-5_all.ipk
```

APK 同版本替换应指定实际本地文件：

```sh
apk --no-network --allow-untrusted add --force-reinstall /tmp/luci-app-proxy-guard-0.3.0-r21.apk
# 仅当需要替换已安装的 Pro 时执行下一行
apk --no-network --allow-untrusted add --force-reinstall /tmp/luci-app-proxy-guard-pro-0.3.1-r5.apk
```

不要仅凭 `apk fix` 返回成功判断本地包已重装；输出中如果出现 `unavailable, skipped`，文件并未替换。

升级前请完成或取消尚未确认的配置试用。安装程序会先回退未确认的试用配置，再保留已确认的设置；直接改写 UCI 文件也需要经过应用和确认流程。

版本号相同不代表文件内容相同；不要先卸载再重装来代替覆盖升级。安装过程中保留完整输出，完成后检查包状态和本插件实际状态。不要同时从多个会话执行安装、应用或重装。

安装后入口为 LuCI“服务 → Proxy Guard / 代理连接保护”。安装钩子会清理 LuCI 缓存、自动重载 rpcd，并按需要重启本插件；这是安装包自身的行为。正常安装不需要额外手工刷新 rpcd。如果菜单或 RPC 仍缺失，应保留安装输出并排查，不要用额外授权掩盖问题。

首次安装默认总开关关闭、仅监测模式。升级会保留修改过的 `/etc/config/proxy_guard`，包括开关和自定义等待时间。安装迁移会更新与已识别旧预设完全一致的检测地址：旧 Google/Cloudflare 默认组合改为 gstatic + Ubuntu，旧 Cloudflare 出口地址改为 ipify；自定义目标组合按实际匹配结果保留。包管理器可能另存待合并的配置副本（如 opkg 的 `proxy_guard-opkg` 或 apk 的 `.apk-new`），须按实际安装输出检查。安装前应自行保存配置副本，升级后检查实际状态，不要直接以新的默认值覆盖旧配置。

安装前的备份至少包括 `/etc/config/proxy_guard`；使用 Pro 时还包括 `/etc/config/proxy_guard_access` 及存在的 `/etc/proxy-guard-access/device.key`、`/etc/proxy-guard-access/path.key`。原始 UCI 导出不会包含这些私有密钥，不能单独充当完整配对备份。备份只应由管理员读取，避免上传公开仓库或问题附件。路由器配置备份不包含 VPS 的 Agent 配置、证书及 Worker Secrets，后者须分别保管。

使用 Pro 时，卸载路由器扩展或停止同步**不会立即删除 VPS 已有规则**。若目的是移除远端访问策略，应在控制链路可用时先执行准备移除、应用并确认，见[远端策略确认](GUIDED-SETUP.md#pro-的远端策略确认)。

需要卸载时执行：

```sh
opkg remove luci-app-proxy-guard-pro  # 仅当已安装 Pro 时先卸载扩展
opkg remove luci-app-proxy-guard
```

APK 固件使用：

```sh
apk del luci-app-proxy-guard-pro  # 仅当已安装 Pro 时先卸载扩展
apk del luci-app-proxy-guard
```

正常卸载会清理本插件的规则、RPC 注册、菜单和启动链接；修改过的配置可能按所用包管理器的配置文件规则保留。卸载会解除本插件的阻断，不能在仍依赖该阻断时把卸载当作维护手段。

## 第一次配置

首次打开新装页面会显示设置引导，可推荐现有 LAN 入口和范围。修改控件只改草稿；保存只暂存，保存并应用才提交。启用后的后端自检通过后，必须在 30 秒内明确确认，否则恢复上次确认的配置和规则；代理故障本身应保持阻断，而不是自动关闭保护。详见[设置引导](GUIDED-SETUP.md)。

1. **本机 SOCKS 端口**：确认代理确实在本机 `127.0.0.1` 对应端口提供 SOCKS5。检测固定经该代理，不会改用直连。默认 `1070` 只是示例，插件不创建代理服务。
2. **出口 IPv4 校验（可选）**：新装默认关闭，不影响连通性和客户端服务检查。勾选校验后才要求填写可信的预期出口 IPv4；Pro 也可通过已保存的认证连接导入 VPS 接口或面板配置提示。导入只改草稿，并不证明代理真实出口；仍需保存并应用。升级保留原有校验选择。
3. **入口设备**：例如实际的 `br-lan`，应选承担三层转发的设备，而非桥内的交换端口。多入口、隧道和容器网络须单独设计并验证。
4. **受保护地址**：先只选一个测试客户端，例如文档地址 `192.0.2.100/32`；实际使用必须替换。公开版的 `192.0.2.0/24`、`198.51.100.0/24`、`10.20.0.0/24` 等都是示例，不是自动发现结果。
5. **IPv6 范围**：引导要求明确选择发现的前缀、手填、`::/0` 或不保护 IPv6；基本设置有独立开关。旧配置未设置该开关时沿用原范围。仅限制 IPv4 不等于仅保护同一台设备；如果只测试一台设备，应同时核对其 IPv6 范围和实际路径。此设置不会关闭系统 IPv6。
6. **局域网例外**：只填写必须保留的实际网段；不要填整个互联网或过宽网段。路由器本机管理、链路本地和多播也有相应例外。
7. **本地代理入口端口**：填写客户端可直接访问的实际代理端口，防止显式设置本机代理绕过保护。它与“用于检测的 SOCKS 端口”含义不同，不应凭猜测填写。
8. **DNS 例外**：默认目标端口为 `53`。如果已有 DNS 重定向实际转到其他本机/获准局域网端口，需填写真实目标端口。例外不保证放行任意外部 DNS，DNS 端口也不能与代理入口端口重叠。插件不会创建或修改 DNS 重定向。
9. **定时安排**：新装定时默认关闭，开始/结束时间、重复方式和星期均不预填。固定 UTC 偏移默认 `UTC+00:00`；升级保留已保存计划。请自行设置每天或每周多选星期，再保存并应用。

先以“仅监测”模式保存并应用。确认网站检查、已启用的出口校验及所需服务检查通过，TCP/UDP/DNS 识别符合实际配置，再切换保护模式。仅监测模式会记录状态与计时，但不安装阻断策略。

## 保存、应用和状态

| 操作 | 效果 |
| --- | --- |
| 勾选、改数字、切换模式 | 只编辑表单，显示未保存更改，不启动保护 |
| 保存 | 暂存当前登录会话的修改，不提交到实际运行配置 |
| 保存并应用 | 校验并提交本插件配置，应用后刷新真实状态 |
| 重置 | 按页面保存/暂存状态重置草稿，不等同于恢复出厂配置 |
| 清空日志 | 清除本插件事件和检查详情，不清除 PassWall 源日志，不解除保护 |

状态约每秒刷新，事件与检查日志约每 5 秒刷新；慢 RPC 会增加可见延迟。状态失联时显示“待检查”，不应根据旧的绿色提示判断仍有保护。现有 LuCI 会话仍受原 ACL 限制，不要为解决页面问题额外授予系统权限。安装 Pro 或更换权限后，旧会话可能需要退出并重新登录。重新登录后仍出现 RPC 对象缺失时，应按安装缺陷排查，保留输出和版本信息；不要把手工刷新 rpcd 当成安装流程已经通过。

## 阻断和恢复的顺序

### 常规代理检查

每轮经本机 SOCKS 请求配置的 HTTPS 连通性目标；只有启用出口 IPv4 校验时，才要求额外取得并核对出口地址。常规模式使用配置的连续失败/恢复次数，默认失败 3 轮、恢复 2 轮。默认网站最少成功数为 1；启用的出口校验和 UDP 检查也必须通过。每轮结束后再等配置间隔，默认等待 10 秒，网络请求耗时另计。

新装默认检测 `https://www.gstatic.com/generate_204|204` 和 `https://connectivity-check.ubuntu.com/|204`，覆盖升级会保留已保存的自定义检测目标。

固定启动宽限默认截至路由器开机后 150 秒；保护模式在等待期间保持阻断。启用开机保护时，改为等待所需服务就绪，再走阻断等待与恢复验证。

开启出口 IPv4 校验后，可以在「连接检测」填写备用 HTTPS 地址。主地址超时才会在同一轮经同一 SOCKS 补查一次，下一轮仍先查主地址。留空时，ipify 使用 https://4.ident.me/，其他主域名不使用备用地址。错误 IPv4、主备都失败、以及阻断和恢复的判定沿用现有规则。

### 代理客户端服务监视

开启客户端服务监视后，约每秒读取本机进程/监听信息和进程身份。默认任意已纳入监视的 TCP、UDP 或 DNS 项停止或重启即触发；也可选择全部所需项同时异常。所需项由当前客户端的实际配置决定，未配置或不需要的组件不一律视为故障；客户端无法识别则应排查适配与配置。

触发后默认阻断 15 秒，期间不做外网探测，仍监视本机服务。等待结束且条件允许时，执行新的代理验证；满足恢复条件才放行。随后在**可联网状态**敏感观察默认 60 秒，每轮结束后约等 1 秒再检测。这一恢复流程中的代理验证与增强监测要求全部 HTTPS 目标、已开启的出口 IPv4 校验和 UDP 检查通过，不沿用常规模式的最少成功目标数。观察期只要再次出现被识别的服务、日志或代理故障，就重新阻断、等待并重新累计观察，不累计常规连续失败阈值。短于采样间隔且未改变进程身份的抖动可能无法捕获。

等待与观察都有独立开关，时长可设 1–3600 秒。关闭等待表示立即开始验证；关闭观察不等于跳过恢复验证。修改设置须保存并应用。

### 代理客户端运行日志

需在服务监视下另行开启日志监视，可设 1–10 秒读取间隔。只读所选客户端运行日志的新增数据，例如 PassWall 的 `/tmp/log/passwall.log`，识别明确的重启、规则删除/清空、停止、启动失败和运行完成消息。普通规则下载、更新完毕及清理日志提示不单独触发。消息按已核对的上游实际语言识别，与插件页面所选语言独立；具体语言和限制见[运行日志兼容说明](LOG_COMPATIBILITY.md)。

首次由日志触发后，等当前启动周期有效的“运行完成”、全部所需服务恢复和新的代理验证通过，直接放行进入敏感观察，不另加一次故障等待。**如果故障发生在已经放行的敏感观察中，仍要执行配置的阻断等待**，后来的完成日志不能提前取消等待。

较旧的完成消息、无效/未来时间和无关的取消重启，不应撤销新的规则删除。时长使用单调时钟；解析日志使用路由器当前时钟与本机时区。源日志无法读取时提示异常并继续其他检查；已由日志触发的等待不会因为文件消失而自动解除。

### 开机保护

只有总开关、保护模式、服务监视及开机保护均开启才生效。在配置有效、环境兼容时，启动阶段先安装按设备名匹配的阻断策略，待设备可核验后替换；等待当前配置要求的 TCP、UDP、DNS 项全部就绪，再经过配置的阻断等待和新的代理验证，放行进入观察。

开机服务就绪等待取代原固定启动宽限。它不能保证在配置损坏、不支持的防火墙/硬件路径或流量绕过设备时仍能保护；启动期接口未创建也可能产生暂态提示，应结合后续状态判断。

### 定时保护

支持每天或每周任意多选星期；跨午夜窗口归属于开始当天。UTC 偏移固定，不修改系统时区，不自动跟随夏令时。开始和结束必须不同，路由器系统时间应准确。

窗口内阻断外网并保留原有例外。开启服务监视时，窗口结束且没有实际故障/未完等待，先执行新的代理验证，通过后放行进入敏感观察，不追加 15 秒等待；否则仍遵循故障流程。未开启服务监视时，窗口结束仍需常规连续恢复验证。

## 升级与重启后的检查

1. 核对安装的版本与 SHA256，确认依赖和安装钩子没有报错。重新登录 LuCI 后检查菜单、页面、状态和日志是否可用。
2. 核对总开关、模式、入口设备、地址范围、例外及原有定时计划是否保留；不能只看表单默认值。
3. 用一个受保护客户端检查实际流量路径；确认阻断与恢复、LAN、DNS、管理和其他网关设备符合预期。
4. 若启用了开机保护，先保留独立的管理通路或本地控制台，再重启**运行 Proxy Guard 的路由器**，使用受保护客户端验证路由器启动阶段的阻断、服务就绪、恢复验证和增强监测顺序。只重启客户端不能验证开机保护。普通重启不会保留 RAM 日志，应提前保存所需记录。
5. 使用 Pro 时，另查控制心跳、家庭授权、已选端口规则和 Agent 服务；动态家庭授权需重新认证，不能把静态规则存在当作动态授权已经恢复。

每次更换固件、代理内核或网络拓扑后，应重新核对上述项目。

## 日志与排障

事件日志和频繁的联网检查详情分开保存；页面分别显示最近 200 条事件和 100 条详情，文件按配置大小轮转。插件日志在 RAM，重启会丢失，并通过 `logger` 写入系统日志；系统若另行配置远程/持久化日志，应由使用者管理。

只读排查可以查看页面，或在自己的路由器执行：

```sh
if command -v opkg >/dev/null 2>&1; then
    opkg status luci-app-proxy-guard
else
    apk info -a luci-app-proxy-guard
fi
/usr/libexec/proxy-guard status
/usr/libexec/proxy-guard logs
```

“触发保护”类 error 级别事件可能表示正确响应了故障，并不自动等于插件崩溃。应检查之后是否恢复、是否有持续规则错误、状态是否失联。不要通过不断调低敏感度或扩大局域网/DNS 例外来掩盖配置问题。分享输出前先按[隐私说明](PRIVACY.md)脱敏。

维护时如果需要解除本插件保护，明确关闭总开关并“保存并应用”；停止检测进程不应当作解除阻断的方法。网关、NAT、DNS 和 PassWall 的调整仍是独立维护操作。

| 现象 | 优先核对 |
| --- | --- |
| 勾选后没有运行 | 是否只改了草稿或点了保存，是否已保存并应用及完成确认。 |
| 仅监测中记录了阻断事件，但仍可联网 | 仅监测不会限制流量，先核对工作模式，不要据此判定防火墙失效。 |
| 检测成功但设备仍被阻断 | 是否在定时窗口、阻断等待、服务/日志等待，或尚未达到连续恢复条件；同时查看真实规则状态。 |
| 网站检查成功，UDP 应用仍失败 | 是否启用且通过 UDP 通路检查，客户端是否支持 UDP ASSOCIATE，实际目标与路由是否不同。 |
| 代理看似正常但反复报出口不符 | 是否启用了出口校验，预期地址是否对应真实代理出口，是否存在 NAT、WARP、多出口或多跳。 |
| 停止插件后仍不能上网 | 停止进程不等于关闭保护；通过总开关应用关闭，并检查系统其他防火墙及代理故障。 |
| 日志不再更新或时间异常 | 查看源日志权限、实际路径、客户端版本与路由器时钟；页面语言不决定上游日志能否识别。 |
| 自检拒绝启用 | 查看具体配置/内核错误，核对 flow offload、flowtable、桥接过滤及入口设备；不要跳过检查或扩大例外。 |
| 已关定时但仍阻断 | 服务故障、代理验证失败、规则异常与定时是独立原因，应按当前状态处理。 |

界面状态的进一步解释见[主页状态说明](USER-GUIDE.md#guide-troubleshooting)。


## UDP 实际通路检查（可选）

包已明确依赖固件软件源的 `luci-lib-nixio`，供文件锁和可选 UDP 检测使用，不依赖独立 flock 包。填写你选定的可达 UDP DNS 服务器 IPv4、端口、查询域名和超时，再通过“保存并应用”启用。模块缺失时会在草稿自检中报错，并拒绝提交开启 UDP 的配置。

检测通过本机 SOCKS5 建立 UDP ASSOCIATE，将带随机事务 ID 的 DNS 请求经本地 UDP 中继转发给所选目标，校验响应来源、事务 ID、问题、返回码等。中继地址必须属于本机回环地址；不接受外部中继，不做直连回退。上游代理未实现 UDP ASSOCIATE 时该检测不能通过。配置应选择适当的外部目标；局域网目标只能验证局域网这一条 UDP 路径。

UDP 验证失败计入本轮失败；日常使用原有连续失败阈值，敏感观察中一次失败即阻断。15 秒故障等待内也不发送 UDP 验证。它不会替代 HTTPS 和出口验证，也不证明全部 UDP 应用或 IPv6 代理出口正常。

## 进程恢复与资源观察

“插件自检与恢复”提供心跳等待、恢复最短间隔、窗口内次数上限和统计窗口。关闭自动恢复后，procd 仍可拉起已退出的服务，但不会因心跳超时主动重启。手动执行 init 脚本 stop 后，不会由心跳守护重新启用；保护模式会保留外网阻断，解除保护请使用总开关。

资源统计每五秒采样，CPU 百分比以全部在线逻辑处理器总容量为 100%，并显示逻辑处理器数量；例如 20 个逻辑处理器中占满一个为整机 5%。计数器重置、逻辑处理器数量或进程身份变化时先重新采样。这是短时近似值，包含三个受守护后台进程及其子进程，未完整计入 LuCI/rpcd、内核和其他代理服务的开销，不能替代长期分析。关闭资源采样不关闭心跳保护。日志存放在内存目录，若系统另行配置持久化或远程 syslog，仍可能产生额外写入或外发。

## Pro：VPS 访问管理

### 端口范围与模式

只限制明确添加并启用的服务规则。监听清单仅供选端口参考，不自动接管。未选端口和 SSH 默认沿用系统原有防火墙规则；“不限来源”也不会覆盖系统防火墙的拒绝规则。动态授权在 Agent 重启后需要重新认证。启动时优先恢复保存的已选端口策略，主状态损坏时使用独立策略缓存；两份策略均无效时不扩大到整机阻断。

保护方式默认 `standard`，可改为 `whitelist` 或 `observe`。每项服务可配置速率、突发量、跟踪连接数、统计窗口及暂停新连接时间。家庭授权和静态允许来源是否免于标准资源限制，取决于该条规则的来源设置；`source_mode=all` 不按这些白名单自动豁免。标准模式保留已有正常连接；白名单模式持续检查已有入站连接的来源授权，授权撤回后也会受限。

### SSH 应急访问

独立代理心跳须经过本机 SOCKS 到 Agent 的 HTTPS 入口，不能复用 Cloudflare 控制通道。认证密钥保存在私有文件中。SSH 托管、管理地址、等待时间及应急来源范围各自可配置；初次启用前先建立允许来源的 SSH 管理会话。新配置的公网应急时长默认为 0：双通道失联达到等待时间后持续开放，直到家庭 IP 授权恢复。可改为 30–3600 秒，限时结束后只保留管理地址及最后认证家庭地址；旧配置的显式时长不会被覆盖。警告：限时到期时，若家庭 IP 已变化且没有可用管理来源，可能无法重新登录 SSH。持续开放会延长 SSH 公网暴露时间，SSH 身份验证和系统防火墙仍然生效。恢复认证并更新家庭授权后才撤销应急入口。RAM 心跳记录避免进程反复重启延后救援。

### 远程维护

远程维护需要 Agent `maintenance.enabled` 及对应动作授权，同时在 LuCI 启用对应动作。`adapter=systemd` 使用本机指定的 Xray 单元；`adapter=3x-ui` 需设置其单元并确认 `xui_usr1_confirmed`，`service` 必须与进程监视项目名称一致。维护队列独立运行，不阻塞认证心跳。

### 可选回落数据源

可选回落数据源在 Agent `reality.telemetry_file` 配置：私有常规 JSONL 文件，禁止其他用户写入，记录须带 Unix 秒 `time`。心跳行示例为 `{"kind":"heartbeat","time":...}`；连接记录包含 `kind`（`authenticated` 或 `fallback`）、`source_ip`、`source_port`、`port`、`protocol`，回落记录另带递增的 `bytes_in`／`bytes_out`。只接受匹配已选端口、时间新鲜的记录；不会自动更改 Xray 配置或启用调试日志。

若 Xray 由非 root 用户运行，可在 `reality.log_uid` 明确指定可信日志所属 UID；日志不得允许组或其他用户写入。回落带宽上限按每个方向、每个来源及所选端口计算，不是整机或全部来源共用限速。

### 面板与订阅端口

Pro 仅过滤已启用且明确选中的服务端口。未选择的独立 3x-ui 面板、API、订阅端口继续遵循系统原有防火墙；选中后则按该服务规则过滤。共用同一 IP、协议、端口的反向代理入口无法按 URL 路径或 SNI 区分，面板与代理可能同时受限。SSH 使用独立设置。不要将远程管理端口误加入业务端口规则；预览监听端口不等于自动纳入保护。

### 每条端口规则独立设置

全局选择仅作为默认模式。每条服务/端口规则可继承默认值，或单独选择仅白名单、标准防滥用、仅观察。规则中可设置 TCP/UDP、端口或端口范围、动态家庭授权/静态白名单/混合来源，并单独设置新连接速率、突发数、并发连接数、可信回落带宽阈值、持续超限时间、冷却时间、观察窗口及对应开关。归在一条规则中的端口共用配置；需要不同配置时请分别建规则。同一协议的已启用端口规则不能重叠。

标准模式执行资源限制，观察模式只记录超限事件，白名单模式依照允许来源放行；明确选择“不限制”会绕过该规则的过滤。SSH 仍使用独立设置。保存只暂存，保存并应用才启用新配置。

启用独立模式前，会先通过认证状态接口核对 Agent/Worker 是否支持该功能；旧服务不支持时，在发送修改前报错。更新时须同步更新 Linux Agent 与所用 Cloudflare Worker；不使用独立模式的旧配置继续继承全局行为。

### 完整原始配置编辑

代理保护和 VPS 访问规则的设置页分别提供“原始 UCI 配置”入口，可编辑各自完整配置，并载入完整默认模板或下载编辑区内容。显示内容包含当前登录会话已暂存的设置。所有受支持的配置项均可直接修改；合法范围、关联条件及系统维护字段仍由后端校验。

保存只写入本会话的 UCI 暂存区，不会直接启用。保存并应用调用原有应用流程；本地代理保护仍执行启用自检和30秒确认/回滚，Pro 的独立端口模式仍先核对远端能力。修改过程中若其他页面已改变配置，将要求重新载入。原始编辑器只针对本插件两份 UCI 配置，沿用各自现有读写权限；不会取得系统文件或任意命令的权限。

已有 token、password、secret 等敏感字段用 `__KEEP_SAVED_SECRET__` 保留，实际私有密钥文件不导出。若需要换密钥，可明确输入新值后保存应用。Pro 的 revision 为防重放的系统维护字段，应用时自动递增。模板替换只改编辑区，仍需手动保存应用。

## 原始配置与实际保护语义

原始配置校验分别显示 UCI 语法是否正确、是否具备启用参数。总开关关闭时可以保存未完成的草稿，但不能把语法通过理解为启用自检通过；未知字段保留并显示警告，旧 `default_deny`/`auto_discover` 不再作为整机拦截功能。

每个端口的 `source_mode=all` 表示允许所有来源连接，不会按家庭或静态白名单自动豁免，标准防滥用仍启用；已验证的代理业务仍按既有可信流量策略处理。仅白名单模式不能配合“所有来源”。旧的 `source_mode=any` 继续保留完全绕过该端口保护的行为，界面明确标为无保护，升级不会静默改变旧规则。状态显示远端确认的有效行为，不能仅凭选择了“标准防护”判断限流已生效。

Pro 默认开启 VPS 策略确认，以及停止同步与移除规则的独立流程，详见[设置引导与确认回退](GUIDED-SETUP.md#pro-的远端策略确认)。

`revision` 是同步协议的递增版本号，由应用后端维护；原始编辑器不能通过填写更低值回退它。重装时应保留配对配置与版本号，避免与已有 VPS 的状态不一致。

LuCI 无法访问、插件停止但仍阻断或 Pro 远端策略遗留时，见[独立故障救援指南](RECOVERY.md)。
