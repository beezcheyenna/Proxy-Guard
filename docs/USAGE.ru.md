## Проверка скачанного файла

Загрузите нужный пакет и `SHA256SUMS` из [одного стабильного выпуска (на английском)](https://github.com/beezcheyenna/Proxy-Guard/releases/tag/v0.3.0-21-pro-0.3.1-5) в один каталог. Сверьте редакцию, формат, версию и имя. Пример для Standard IPK. Для Standard APK укажите `PG_PACKAGE=luci-app-proxy-guard-0.3.0-r21.apk`.

```sh
PG_PACKAGE=luci-app-proxy-guard_0.3.0-21_all.ipk
awk -v f="$PG_PACKAGE" '$2 == f { print; n++ } END { if (n != 1) exit 1 }' SHA256SUMS > SHA256SUMS.selected &&
sha256sum -c SHA256SUMS.selected
```

Убедитесь, что выбранный файл получил `OK` и команда завершилась успешно. Пропуск, дубликат, отсутствие файла или несовпадение суммы требуют остановить установку. Для полного набора используйте `sha256sum -c SHA256SUMS`. При частичной загрузке проверка всего списка выдаст ошибки для отсутствующих файлов.

На macOS выполните `shasum -a 256 <имя файла>` и сравните все 64 шестнадцатеричные цифры. SHA256 сверяет файл с манифестом. Получайте оба из HTTPS-выпуска проекта. Для проверки издателя нужна отдельно проверяемая подпись или аттестация.

## Установка, обновление и удаление

Выберите формат прошивки. Для opkg в серии 24 нужен IPK, для apk в 25.12 — APK. Загрузите через LuCI либо положите файл на роутер и выполните соответствующую команду.

**opkg / IPK**

```sh
opkg install /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk
```

**apk / APK**

```sh
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-0.3.0-r21.apk
```

`--allow-untrusted` разрешает вручную проверенный локальный APK. Зависимости продолжают проверяться. `--no-network` требует уже установленных зависимостей. Недостающие сначала установите из источников прошивки.

Pro расширяет совместимый Standard и имеет свою версию. Оба пакета можно установить одной транзакцией.

**opkg / IPK**

```sh
opkg install /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk /tmp/luci-app-proxy-guard-pro_0.3.1-5_all.ipk
```

**apk / APK**

```sh
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-0.3.0-r21.apk /tmp/luci-app-proxy-guard-pro-0.3.1-r5.apk
```

Если установленный Standard удовлетворяет минимуму и базовому API, обновляйте только Pro. Несовместимость отклоняется с причиной. Исправления Standard также можно обновлять отдельно при совместимости. См. [сравнение версий](EDITION-MATRIX.ru.md). Для удалённых функций отдельно нужен [Linux Agent](LINUX-AGENT-INSTALL.ru.md) и прямой HTTPS либо Cloudflare Worker/Tunnel/VPC.

С Pro 0.3.1-2 установка и запуск переносят прежние UCI `device_token` и `path_token` в файлы только для root, даже при выключенном плагине. Новые секреты сохраните и примените через LuCI. Если прежние значения были доступны недоверенным аккаунтам, замените их на устройствах и сопутствующих службах.

Standard зависит от `luci-base`, `lua`, `libuci-lua`, `luci-lib-jsonc`, `luci-lib-nixio`, `rpcd-mod-file`, `firewall4`, `curl`, `ca-bundle`, `ucode`, `ucode-mod-fs` и `ucode-mod-uci`. Берите зависимости для конкретной прошивки и готовьте их до офлайн-установки. Отдельный `flock` не нужен. Сохраняйте проверку зависимостей.

Обычная установка может пропустить сборку с той же версией. Сделайте копию, проверьте источник и SHA256. Вторую команду выполняйте только для замены установленного Pro. Для apk укажите локальный файл.

**opkg / IPK**

```sh
opkg install --force-reinstall /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk
opkg install --force-reinstall /tmp/luci-app-proxy-guard-pro_0.3.1-5_all.ipk
```

**apk / APK**

```sh
apk --no-network --allow-untrusted add --force-reinstall /tmp/luci-app-proxy-guard-0.3.0-r21.apk
apk --no-network --allow-untrusted add --force-reinstall /tmp/luci-app-proxy-guard-pro-0.3.1-r5.apk
```

`unavailable, skipped` у `apk fix` означает, что файлы не заменены. Завершите или отмените пробные настройки до обновления. Установщик откатывает неподтверждённое и сохраняет подтверждённое. Обновляйте поверх, сохраняйте вывод, выполняйте действия в одном сеансе.

В LuCI откройте **Службы → Proxy Guard**. Обработчики чистят кеш, перечитывают rpcd и перезапускают плагин при необходимости. Если после повторного входа меню или объекта RPC нет, сохраните вывод и проверьте зависимости и обработчики. Оставьте действующие ACL.

Новая установка выключена и в режиме наблюдения. Обновление сохраняет `/etc/config/proxy_guard`, переключатели и сроки. Точное совпадение со старыми Google/Cloudflare переносится на gstatic и Ubuntu, старый выход Cloudflare — на ipify. Сверьте реальные цели и копии `proxy_guard-opkg` или `.apk-new`.

Сохраните `/etc/config/proxy_guard`. Для Pro также `/etc/config/proxy_guard_access` и существующие `/etc/proxy-guard-access/device.key` и `/etc/proxy-guard-access/path.key`. Экспорт UCI не включает эти ключи. Храните копии закрыто, отдельно от конфигурации Agent, сертификатов и секретов Worker.

Остановка Pro или удаление расширения оставляет политику VPS. Пока есть управление, подготовьте удаление, примените, подтвердите и проверьте VPS. См. [подтверждение удалённой политики](GUIDED-SETUP.ru.md#remote-policy-confirmation).

Выберите команды менеджера пакетов. Первая строка нужна только при установленном Pro.

**opkg / IPK**

```sh
opkg remove luci-app-proxy-guard-pro
opkg remove luci-app-proxy-guard
```

**apk / APK**

```sh
apk del luci-app-proxy-guard-pro
apk del luci-app-proxy-guard
```

Удаляются правила, регистрация RPC, меню и ссылки запуска. Менеджер пакетов может сохранить изменённый конфиг. Блокировка плагина снимается. Для обслуживания см. [явное отключение](RECOVERY.ru.md).

## Первичная настройка

В [мастере](GUIDED-SETUP.ru.md) выберите фактический вход LAN третьего уровня и проверьте [настройки](USER-GUIDE.ru.md#guide-options). Начните с одного устройства и обоих семейств. Адреса в пакете служат примерами. Сверьте реальный SOCKS5 на `127.0.0.1`, входы прокси для клиентов и целевые DNS-порты. Порт проверки и клиентский вход различаются. DNS по умолчанию `53`. Оставьте необходимые локальные исключения и явно исключите IPv6 при необходимости. Примените **только наблюдение** и проверьте реальный путь.

## Сохранение и применение

Изменения остаются черновиком. **Сохранить** подготавливает их для сеанса, **Сохранить и применить** проверяет и фиксирует. После самопроверки подтвердите за **30 секунд**. Сброс возвращает сохранённые или подготовленные значения формы. Очистка журнала удаляет только события и проверки плагина. Статус обновляется примерно раз в секунду, журналы раз в пять. Медленный RPC задерживает интерфейс. При устаревшем статусе сверяйте ядро. После смены прав войдите снова. См. [статус и диагностику](USER-GUIDE.ru.md#guide-troubleshooting).

## Блокировка и восстановление

### Обычные проверки

HTTPS идёт через локальный SOCKS. Выходной IPv4 и SOCKS5 UDP необязательны. Цели новой установки: `https://www.gstatic.com/generate_204|204` и `https://connectivity-check.ubuntu.com/|204`. По умолчанию нужен один успешный сайт и все включённые проверки адреса и UDP. Три неудачи запускают защиту, два успеха восстанавливают доступ. Пауза 10 секунд начинается после завершения раунда. Стартовая отсрочка по умолчанию до 150-й секунды загрузки с блокировкой в режиме защиты. Защита загрузки заменяет её ожиданием служб.

При включённой проверке IPv4 только тайм-аут основной цели запускает один резервный HTTPS через тот же SOCKS. Следующий раунд опять начинает с основной. Пустое поле даёт ipify резерв `https://4.ident.me/`, для прочих доменов резерва нет. Чужой адрес или неудача идут по действующим правилам.

### Наблюдение за службами

Процессы и слушатели проверяются примерно раз в секунду. По умолчанию остановка или перезапуск любого требуемого TCP, UDP или DNS включает защиту. Можно потребовать сбой всех отслеживаемых. Состав зависит от конфигурации клиента.

Ожидание блокировки по умолчанию 15 секунд без внешних запросов. После ожидания и готовности служб новая проверка разрешает трафик при успехе. Затем по умолчанию 60 секунд усиленного наблюдения со связью при исправности и паузой около секунды после раунда. Для восстановления и усиленного наблюдения нужны все HTTPS-цели и включённые проверки адреса и UDP. Повторный сбой возвращает блокировку сразу. Ожидание и усиленное наблюдение имеют отдельные переключатели и длительности 1–3600 секунд. Проверка восстановления сохраняется.

### Журналы выполнения

Включите чтение отдельно в наблюдении за службами. Интервал 1–10 секунд. Проверенные сообщения о перезапуске, правилах, остановке, ошибке и завершении описаны в [совместимости журналов](LOG_COMPATIBILITY.ru.md). При первом сбое по журналу свежее завершение текущего цикла, службы и новая проверка могут сразу разрешить связь с усиленным наблюдением. При повторе в усиленном наблюдении ожидание обязательно. Пропуск журнала, старые и будущие метки или посторонняя отмена не снимают ожидающий сбой. Задержки монотонны, метки журнала используют локальные часы и зону роутера.

### Загрузка и расписание

Защита загрузки требует основного переключателя, режима защиты, наблюдения за службами и отдельной настройки загрузки. При валидной конфигурации раннее правило по имени устройства сверяется после появления интерфейса. До ожидания и восстановления должны подняться требуемые TCP, UDP и DNS. Проверьте реальный путь.

Выберите ежедневное или недельное повторение, разные начало и конец и фиксированное смещение UTC. Ночной интервал относится к дню начала. В окне сохраняются исключения, внешний доступ блокируется. По окончании с наблюдением за службами и без иных сбоев или ожидания новая строгая проверка переводит в усиленное наблюдение без дополнительных 15 секунд. Без наблюдения действуют обычные последовательные проверки восстановления.

## Проверка обновления и перезагрузки

1. Проверьте версию, SHA256, зависимости и обработчики. Войдите заново и проверьте страницу, статус и журнал.
2. Сверьте сохранённые переключатели, режим, вход, диапазоны, исключения и расписание.
3. С одного клиента проверьте новые и старые соединения, блокировку, восстановление, LAN, DNS, управление и другой шлюз.
4. Сохраните журнал RAM и независимый канал. Для защиты загрузки перезагрузите **роутер с Proxy Guard** и проверьте стартовое поведение с клиента.
5. Для Pro проверьте управление, свежую домашнюю авторизацию, выбранные правила и Agent. Повторите при смене прошивки, ядра прокси или схемы сети.

## Журналы и диагностика

Видны последние 200 событий и 100 проверок. Файлы в RAM ротируются по размеру. `logger` пишет также в системный журнал. Событие защиты с уровнем error может быть нормальной реакцией. Проверьте восстановление, ошибки правил и актуальность состояния. См. [статус](USER-GUIDE.ru.md#guide-troubleshooting), [приватность](PRIVACY.ru.md) и [восстановление](RECOVERY.ru.md).

Команды чтения на роутере:

```sh
if command -v opkg >/dev/null 2>&1; then
    opkg status luci-app-proxy-guard
else
    apk info -a luci-app-proxy-guard
fi
/usr/libexec/proxy-guard status
/usr/libexec/proxy-guard logs
```

## Необязательная проверка UDP

Укажите доступный IPv4 DNS по UDP, порт, имя запроса и тайм-аут. `luci-lib-nixio` даёт блокировки и UDP. При отсутствии поддержки самопроверка отклоняет включение. Используется SOCKS5 UDP ASSOCIATE, ретранслятор на loopback и случайный ID DNS. Проверяются источник, ID, вопрос и код ответа. Клиент должен поддерживать этот режим. Локальная цель подтверждает только локальный путь.

Ошибка UDP засчитывается как неудача раунда, а при усиленном наблюдении сразу блокирует. При ожидании UDP не отправляется. HTTPS и включённая проверка выхода выполняются отдельно.

## Восстановление процессов и ресурсы

Настраиваются ожидание heartbeat, минимальный интервал, число попыток и окно. procd поднимает завершившиеся службы даже при выключенном восстановлении по heartbeat. Явный init stop не включает их обратно и может сохранить блокировку. См. [явное отключение](RECOVERY.ru.md).

Сэмпл каждые пять секунд. 100% — суммарная мощность онлайн-логических CPU, один из 20 — 5%. Сброс счётчиков, смена числа CPU и процесса начинают новый сэмпл. Считаются три наблюдаемых процесса и их потомки, отдельно от LuCI/rpcd, ядра и других прокси. Сбор и heartbeat выключаются независимо. Системный журнал может сохраняться или пересылаться.

## Pro: доступ к VPS

См. [архитектуру](PRO-COMPANION.ru.md), [установку Agent](LINUX-AGENT-INSTALL.ru.md) и [удалённое подтверждение](GUIDED-SETUP.ru.md#remote-policy-confirmation).

- Явно выбирайте локальные порты. Отдельные невыбранные панель, API и подписки следуют системному экрану. Общий IP/протокол/порт нельзя разделить по URL или SNI. SSH настраивается отдельно.
- Правило наследует режим или выбирает `standard`, `whitelist` или `observe`. Отдельно задаются TCP/UDP, диапазоны, домашние, статические или смешанные источники, скорость, всплеск, число соединений, пороги fallback, время превышения, задержка и окно. Включённые порты одного протокола не перекрываются. Standard сохраняет штатные соединения. Отзыв допуска влияет и на входящие установленные.
- Для SSH нужны управление, отдельный HTTPS-сигнал через SOCKS и доступный сеанс управления. Новый публичный аварийный срок `0` действует до восстановления авторизации, альтернативно `30`–`3600` секунд. Прежние явные значения, SSH и системные правила сохраняются. См. [каналы](LINUX-AGENT-INSTALL.ru.md#control-and-path).
- Обслуживание требует `maintenance.enabled` на Agent и разрешения LuCI. `adapter=systemd` использует юнит, `adapter=3x-ui` требует `xui_usr1_confirmed`. `service` совпадает с именем наблюдаемой службы. Очередь независима от сигналов.
- Для точного fallback нужен закрытый обычный JSONL `reality.telemetry_file`. Сигнал имеет `{"kind":"heartbeat","time":...}`. Свежие записи содержат Unix-секунды `time`, `kind` (`authenticated` или `fallback`), `source_ip`, `source_port`, `port`, `protocol`. Fallback также имеет растущие `bytes_in` и `bytes_out`. Сопоставляются выбранные порты, ограничение на направление, источник и порт. Доверенного владельца не root укажите через `reality.log_uid`. Запись группой и другими пользователями запрещена.

## UCI и действующая политика

Редакторы работают с отдельными файлами плагина, черновиком сеанса, шаблоном и выгрузкой. Синтаксис и готовность к включению проверяются отдельно. Сохранение подготавливает, применение запускает локальную или удалённую проверку и подтверждение. При правке в другой вкладке перечитайте конфигурацию. Неизвестные поля остаются с предупреждением. Старые `default_deny` и `auto_discover` не включают общую блокировку.

`__KEEP_SAVED_SECRET__` сохраняет секрет без выгрузки ключа. Для замены введите новое значение. `revision` растёт на сервере для защиты от повторов. Сохраните связку и ревизию при переустановке. Шаблон меняет черновик.

`source_mode=all` допускает все источники в выбранном режиме с ограничениями Standard и без автоматических исключений. Со списком допуска не сочетается. Старое `source_mode=any` сохраняет режим без защиты этого порта. Проверьте подтверждённое удалённое состояние. При недоступном LuCI используйте [восстановление](RECOVERY.ru.md).
