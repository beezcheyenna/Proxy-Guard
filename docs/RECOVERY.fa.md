# بازیابی

[English](RECOVERY.en.md) · [简体中文](RECOVERY.md) · [日本語](RECOVERY.ja.md) · [Русский](RECOVERY.ru.md) · [فارسی](RECOVERY.fa.md)

**پس از توقف سرویس Proxy Guard ممکن است قواعد دیوار آتش همچنان دسترسی را مسدود کنند.** برای برداشتن مسدودی افزونه، محافظت را با مراحل زیر صریحاً غیرفعال کنید.

**موفقیت «آزمایش پراکسی فعلی» فقط دسترسی همان درخواست آزمایشی را تأیید می‌کند.** زمان‌بندی، درخواست API یا ناموفق بودن یک بررسی مستقل همچنان می‌تواند باعث مسدودی باشد.

## وضعیت بازیابی را بررسی کنید

در پنل وضعیت، اجرای فعلی قواعد و نتیجهٔ آخرین بررسیِ کامل‌شده جدا نمایش داده می‌شوند. اگر قواعد نیاز به بررسی دارند، «بررسی تنظیمات و محیط اجرا» را باز کنید. «آزمایش پراکسی فعلی» مسیر SOCKS را بررسی می‌کند.

اگر اتصال پروکسی قطع شد، بررسی کنید که SOCKS محلی کلاینت اتصال می‌پذیرد. پس از بارگذاری دوبارهٔ قواعد یا راه‌اندازی مجدد پروکسی، منتظر بررسی‌های بازیابی بمانید.

پیش از آزمایش بازیابی، کنسول یا مسیر مدیریتی جدا داشته باشید. اگر تنظیمات تازه دسترسی را قطع کرد، منتظر پایان مهلت تأیید بمانید. پس از پایان مهلت یا راه‌اندازی دوباره پیش از تأیید، تنظیمات پیشین بازمی‌گردند.

اگر به کنسول روتر دسترسی دارید، با دستورهای زیر محافظت را صریحاً خاموش کنید. خاموش بودن مسدودسازی را بررسی کنید و سپس دسترسی یک دستگاه تحت محافظت را بیازمایید.

```sh
umask 077
cp /etc/config/proxy_guard /root/proxy_guard.before-recovery &&
uci set proxy_guard.main.enabled='0' &&
uci commit proxy_guard &&
printf '%s\n' '{}' | ucode /usr/lib/proxy-guard/setup-lock.uc apply &&
/etc/init.d/proxy-guard restart &&
ubus call proxy_guard status
```

محافظت فقط ترافیکی را پوشش می‌دهد که از روتر می‌گذرد. پیش از گسترش محدوده، مسیر IPv4 و IPv6، ورودی، DNS و مدیریت را با یک دستگاه بررسی کنید. ترافیک برگشت ممکن است روتر هم‌زیرشبکه را دور بزند.
