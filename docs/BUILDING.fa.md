دستور ساخت بسته‌ها نسخهٔ `0.3.0-21` را برای استاندارد و `0.3.1-5` را برای Pro مشخص می‌کند. این صفحه ساختار کد، ساخت IPK و APK و آزمون‌های توسعه را شرح می‌دهد. هر خروجی را با جمع‌های SHA256 همان ساخت بررسی کنید.

## ساختار کد منبع

| مسیر | محتوا |
| --- | --- |
| `package/root/` | فایل‌های نصب استاندارد |
| `package/pro/root/` | فایل‌های نصب Pro |
| `package/Makefile` | فراداده و اسکریپت‌های نصب و حذف بسته‌های OpenWrt |
| `package/i18n/` | متن پیام‌ها، فهرست‌های PO و فرادادهٔ تولید برای پنج زبان |
| `companion/vps/` | Linux Agent، پیکربندی نمونه و نصب‌کنندهٔ محدود به مؤلفه |
| `companion/worker/` | الگوی Worker، فایل قفل وابستگی‌ها و آزمون‌ها |
| `tests/` | آزمون‌های واحد، رابط و آزمون‌های بومی یا شبکه‌ای نیازمند محیط اختصاصی |
| `LICENSES/` | متن مجوزها و نسخهٔ اطلاعیه‌های پروژه‌های بالادست |

استاندارد و Pro جداگانه قابل ساخت‌اند. Linux Agent و Worker در `companion/` قرار دارند.

## ساخت جداگانهٔ IPK

در نسخهٔ کاری لینوکس به Python 3 نیاز دارید. کد منبع شامل ترجمه‌های تولیدشده است. اگر متن پیام‌ها تغییر نکرده، دانلود LuCI و اجرای ابزار ترجمه لازم نیست. دستورهای زیر به‌ترتیب استاندارد، Pro و هر دو بسته را می‌سازند؛ مورد لازم را انتخاب کنید.

```sh
python3 -B tools/build_ipk.py --only standard
python3 -B tools/build_ipk.py --only pro
python3 -B tools/build_ipk.py
```

ساخت فقط Pro، تداخل مالکیت فایل‌ها با بستهٔ پایه را نیز بررسی می‌کند. بسته‌ها، `SHA256SUMS` و فهرست فایل‌ها در `dist/` قرار می‌گیرند. سازنده اسکریپت نصب را اجرا نمی‌کند و به دستگاهی متصل نمی‌شود.

پس از تغییر متن پیام‌ها، `po2lmo` را از کد رسمی نسخهٔ متناظر LuCI تهیه کنید. برای بازتولید فقط فهرست ترجمه و صفحات اختصاصی Pro، `--only pro` را اضافه کنید.

```sh
python3 -B tools/build_translations.py /path/to/po2lmo
```

پس از تغییر LMO یا نگاشت پیام‌های تشخیصی، فرادادهٔ تولید را نیز به‌روز کنید. ابزارهای LuCI، SDK، کامپایلر متقاطع و هسته‌های پروکسی از پروژه‌های مربوط دریافت می‌شوند.

## OpenWrt SDK

پوشهٔ `package/` پروژه را در `package/` نسخهٔ سازگار OpenWrt SDK قرار دهید و طبق روال SDK، `luci-app-proxy-guard` یا `luci-app-proxy-guard-pro` را برای ساخت انتخاب کنید. وابستگی‌ها را از مخزن متناسب با مقصد بگیرید. برچسب معماری `all` نشان‌دهندهٔ بستهٔ اسکریپتی است.

APK برای 25.12 را با SDK رسمی و متناظر به‌صورت بومی بسازید. `tools/build_ipk.py` فقط IPK تولید می‌کند. شماره‌های APK به‌شکل `0.3.0-r21` و `0.3.1-r5` نوشته می‌شوند. دستور ساخت، اسکریپت‌های نصب، ارتقا و حذف APK و حداقل نسخهٔ استاندارد برای Pro را متناسب با قالب بسته حفظ می‌کند.

دستور SDK و سازندهٔ Python از درخت‌های نصب یکسان استفاده می‌کنند و اسکریپت‌ها را بر اساس مدیر بسته انتخاب می‌کنند. `tools/test_sdk_staging.py` آماده‌سازی، مجوزهای فایل و اسکریپت‌های دو بستهٔ ساخته‌شده را در ماشین مجازی ایزوله با نشانگر آزمون مقایسه می‌کند. زنجیرهٔ کامل ابزار با ساخت مستقل SDK بررسی می‌شود.

متن مجوز و اطلاعیه‌ها در درخت نصب قرار دارند. فایل‌های مجوز Pro جدا از استاندارد نصب می‌شوند.

## آزمون‌های پایه

دستور زیر را در ماشین مجازی اختصاصی و آمادهٔ Linux یا OpenWrt اجرا کنید:

```sh
python3 -B tools/test_standard_pro.py
```

Python 3، Node.js، make و وابستگی‌های دیگر لازم‌اند. بعضی بررسی‌های نسخه و آماده‌سازی SDK به نشانگر `/etc/pgvm-fixture` نیاز دارند که تصویر اختصاصی آزمون فراهم می‌کند. این نشانگر را دستی روی میزبان توسعه نسازید.

آزمون Lua/ucode بومی، اسکریپت‌های نصب، LuCI/UCI/RPC واقعی، مرورگر، فضای نام شبکه، بسته‌های TCP/UDP و راه‌اندازی سرد به تصویر و داده‌های آزمون مناسب نیاز دارد. بعضی اسکریپت‌ها پوشهٔ کاری مشخصی می‌خواهند. دیسک ماشین مجازی و اطلاعات ورود محیط عملیاتی همراه مخزن نیستند.

برای بررسی LMO و gettext واقعی LuCI، `cbi.js` متناظر از منبع رسمی را با `PG_LUCI_CBI` معرفی کنید. نتیجهٔ شبیه‌سازی و آزمون یکپارچگی در محیط واقعی را جداگانه ثبت کنید.

## Worker

در نسخهٔ کاری جداگانه روی لینوکس، ابزارها را طبق فایل قفل نصب کنید. برای آزمون ابری از منابع آزمایشی کنترل‌شده استفاده کنید.

```sh
cd companion/worker
npm ci
npm test
```

`npm test` محیط اجرای محلی را بررسی می‌کند. دستورهای استقرار، رمزها و اتصال منابع در [راهنمای Worker](CLOUDFLARE-WORKER.fa.md) آمده‌اند. پیش از استقرار، تنظیمات و اتصال‌های حساب مقصد را بررسی کنید.

## پوشش آزمون

منطق، نصب، رابط، بازیابی، IPv4/IPv6، راه‌اندازی سرد، سازگاری چند سیستم و اتصال Cloudflare آزموده شده‌اند. پس از تغییرات، آزمون مرتبط را اجرا کنید. [سازگاری](COMPATIBILITY.fa.md) و [ماتریس آزمون‌ها](TEST-MATRIX.fa.md) را ببینید.
