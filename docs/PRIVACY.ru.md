# Конфиденциальность и сетевые запросы

## Какие запросы выполняет плагин

Проверка соединения по умолчанию и необязательная официальная проверка адреса используют HTTPS проекта через локальный SOCKS. Оператор сервиса видит исходящий адрес прокси, время и путь запроса. Кнопка «Запустить подробную диагностику» обращается к `/f` через локальный SOCKS. Авторизованные запросы на обновление через API также могут использовать `/f`, если он выбран. Ответ может содержать исходящий адрес, приблизительное местоположение и сетевые данные.

Выбранные сторонние сервисы проверки соединения или выходного IPv4 также видят адрес источника и время запроса.

Необязательные UDP-проверки DNS выполняются при включённых настройках и выполненных условиях. DNS-сервер получает указанное имя запроса. Частота обращений зависит от интервалов, ожидания, усиленного контроля и длительности запросов. Доступность сторонних сервисов и отсутствие ограничений частоты не гарантируются.

Контроль процессов, сокетов, интерфейсов и журналов читает локальную информацию. Плагин не отправляет эти данные сопровождающему проекта.

## Хранение данных

Плагин хранит настройки UCI, состояние подтверждения и отката, текущее состояние, события и результаты проверок. Рабочие журналы обычно находятся в RAM и теряются при перезагрузке. Отдельно настроенные постоянные или удалённые системные журналы могут сохранять или пересылать эти данные.

UUID API хранится в оперативной памяти. При перезагрузке роутера с включённым API создаётся новый UUID. Авторизованные ответы и журнал для администраторов плагина содержат UUID. Для внешней подробной диагностики используется отдельное случайное значение.

## Публикация отчётов и снимков экрана

Обычные ошибки можно описывать в открытых Issue, исключив из отчёта конфиденциальные данные. Не публикуйте подробности неисправленных уязвимостей.

Перед отправкой проверьте IP, домены, имена аккаунтов, идентификаторы устройств, токены, SOCKS-аутентификацию, адреса панелей и подписок, параметры URL, Cookies, заголовки Authorization, HAR и закрытые ключи. Для примеров топологии подходят `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24` и `2001:db8::/32`.

Снимки README показывают настоящий интерфейс с демонстрационными значениями названия клиента, адресов, времени и использования ресурсов. Это иллюстрации, а не измерения пользовательской системы или подтверждение совместимости клиента. Поддерживаемые конфигурации указаны в [примечаниях о совместимости](COMPATIBILITY.ru.md). Не переносите адреса-заполнители в рабочую конфигурацию.

## Защита конфигурации и ключей

Храните реальные настройки, ключи устройств, ключи сертификатов и копии журналов в защищённом хранилище вне публичных репозиториев. Тестовые секреты и значения из примеров не подходят для эксплуатации. Сохраняйте уведомления об авторских правах третьих сторон: открытые сведения об авторах не являются пользовательскими секретами.

Перед публикацией проверьте новые файлы и историю Git. При утечке сначала отзовите или замените ключи, затем удалите раскрытые данные и соответствующую историю.
