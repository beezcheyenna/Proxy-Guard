نصب، پیکربندی و نگهداری استاندارد `0.3.0-21` و Pro `0.3.1-5`. [سازگاری](COMPATIBILITY.fa.md)، [ماتریس آزمون](TEST-MATRIX.fa.md) و [راهنمای کاربر](USER-GUIDE.fa.md) را ببینید.

## بررسی فایل دانلودشده

بسته و `SHA256SUMS` را از [همان انتشار پایدار (انگلیسی)](https://github.com/beezcheyenna/Proxy-Guard/releases/tag/v0.3.0-21-pro-0.3.1-5) در یک پوشه بگیرید. ویرایش، قالب، نسخه و نام را تطبیق دهید. نمونه برای IPK استاندارد است. برای APK استاندارد، `PG_PACKAGE=luci-app-proxy-guard-0.3.0-r21.apk` بدهید.

```sh
PG_PACKAGE=luci-app-proxy-guard_0.3.0-21_all.ipk
awk -v f="$PG_PACKAGE" '$2 == f { print; n++ } END { if (n != 1) exit 1 }' SHA256SUMS > SHA256SUMS.selected &&
sha256sum -c SHA256SUMS.selected
```

فایل انتخابی باید `OK` و فرمان باید موفق باشد. مدخل حذف‌شده یا تکراری، نبود فایل یا تفاوت جمع، دلیل توقف نصب است. اگر همهٔ فایل‌ها را گرفته‌اید، `sha256sum -c SHA256SUMS` را اجرا کنید. بررسی همهٔ فهرست هنگام دانلود جزئی برای فایل‌های دیگر خطا می‌دهد.

در macOS، `shasum -a 256 <نام فایل>` را اجرا و هر ۶۴ رقم شانزده‌شانزدهی را تطبیق دهید. SHA256 فایل را با فهرست می‌سنجد. هر دو را از انتشار HTTPS پروژه بگیرید. تأیید هویت ناشر به امضا یا گواه قابل بررسی مستقل نیاز دارد.

## نصب، ارتقا و حذف

قالب متناظر فریم‌ور را بگیرید. opkg در سری 24 از IPK و apk در 25.12 از APK استفاده می‌کند. از LuCI بارگذاری کنید یا فایل را روی روتر قرار دهید و دستور متناظر را اجرا کنید.

**opkg / IPK**

```sh
opkg install /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk
```

**apk / APK**

```sh
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-0.3.0-r21.apk
```

`--allow-untrusted` اجازهٔ APK محلی بررسی‌شده را می‌دهد. وابستگی همچنان بررسی می‌شود. `--no-network` وابستگی نصب‌شده می‌خواهد. موارد کم را ابتدا از مخزن همان فریم‌ور بگیرید.

Pro افزونهٔ استاندارد سازگار است و نسخهٔ مستقل دارد. هر دو بسته را می‌توان در یک تراکنش نصب کرد.

**opkg / IPK**

```sh
opkg install /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk /tmp/luci-app-proxy-guard-pro_0.3.1-5_all.ipk
```

**apk / APK**

```sh
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-0.3.0-r21.apk /tmp/luci-app-proxy-guard-pro-0.3.1-r5.apk
```

اگر استاندارد نصب‌شده حداقل نسخه و API پایه را دارد، فقط Pro را ارتقا دهید. ناسازگاری همراه علت رد می‌شود. اصلاح استاندارد هم در محدودهٔ سازگار مستقل است. [مقایسهٔ نسخه‌ها](EDITION-MATRIX.fa.md) را ببینید. قابلیت راه‌دور به [Linux Agent](LINUX-AGENT-INSTALL.fa.md) جداگانه و انتخاب HTTPS مستقیم یا Cloudflare Worker/Tunnel/VPC نیاز دارد.

از Pro 0.3.1-2، نصب و آغاز حتی در حالت خاموش، `device_token` و `path_token` قدیمی UCI را به فایل‌هایی که فقط root اجازهٔ خواندن آن‌ها را دارد منتقل می‌کند. رمز تازه را در LuCI ذخیره و اعمال کنید. اگر قبلاً حساب غیرمطمئن دسترسی خواندن داشت، رمز را در دستگاه و سرویس‌های همراه عوض کنید.

وابستگی استاندارد `luci-base`، `lua`، `libuci-lua`، `luci-lib-jsonc`، `luci-lib-nixio`، `rpcd-mod-file`، `firewall4`، `curl`، `ca-bundle`، `ucode`، `ucode-mod-fs` و `ucode-mod-uci` است. موارد متناظر را پیش از نصب آفلاین آماده کنید. بستهٔ جداگانهٔ `flock` لازم نیست. بررسی وابستگی را حفظ کنید.

نصب معمول ممکن است ساخت تازه با همان شماره را رد کند. پشتیبان بگیرید و منبع و SHA256 را بسنجید. خط دوم فقط برای جایگزینی Pro نصب‌شده است. در apk فایل محلی را مشخص کنید.

**opkg / IPK**

```sh
opkg install --force-reinstall /tmp/luci-app-proxy-guard_0.3.0-21_all.ipk
opkg install --force-reinstall /tmp/luci-app-proxy-guard-pro_0.3.1-5_all.ipk
```

**apk / APK**

```sh
apk --no-network --allow-untrusted add --force-reinstall /tmp/luci-app-proxy-guard-0.3.0-r21.apk
apk --no-network --allow-untrusted add --force-reinstall /tmp/luci-app-proxy-guard-pro-0.3.1-r5.apk
```

`unavailable, skipped` در `apk fix` یعنی فایل جایگزین نشده. قبل از ارتقا اجرای آزمایشی را تأیید یا لغو کنید. نصب‌کننده ابتدا تغییر تأییدنشده را برمی‌گرداند و تنظیم تأییدشده را حفظ می‌کند. روی نسخهٔ موجود ارتقا دهید، خروجی را نگه دارید و عملیات را هم‌زمان از چند نشست اجرا نکنید.

در LuCI، **سرویس‌ها → Proxy Guard** را باز کنید. اسکریپت نصب حافظهٔ نهان را پاک و rpcd را بازخوانی و در صورت نیاز افزونه را راه‌اندازی می‌کند. اگر پس از ورود دوباره منو یا RPC نبود، خروجی، وابستگی و اسکریپت نصب را بررسی کنید. ACL موجود را حفظ کنید.

نصب تازه خاموش و حالت فقط پایش است. ارتقا `/etc/config/proxy_guard`، کلیدها و زمان‌های سفارشی را نگه می‌دارد. پیش‌تنظیم قدیمی دقیق Google/Cloudflare به gstatic و Ubuntu و خروجی قدیمی Cloudflare به ipify منتقل می‌شود. هدف واقعی و نسخهٔ `proxy_guard-opkg` یا `.apk-new` را بررسی کنید.

از `/etc/config/proxy_guard` پشتیبان بگیرید. در Pro، `/etc/config/proxy_guard_access` و فایل‌های موجود `/etc/proxy-guard-access/device.key` و `/etc/proxy-guard-access/path.key` را هم نگه دارید. خروجی UCI این کلیدها را ندارد. پشتیبان خصوصی باشد و تنظیم Agent، گواهی و اسرار Worker جداگانه ذخیره شوند.

توقف Pro یا حذف افزونه سیاست VPS را نگه می‌دارد. تا کنترل برقرار است، حذف را آماده، اعمال و تأیید و قانون VPS را بررسی کنید. [تأیید سیاست راه‌دور](GUIDED-SETUP.fa.md#remote-policy-confirmation) را ببینید.

فرمان مدیر بسته را انتخاب کنید. خط اول فقط وقتی Pro نصب است اجرا می‌شود.

**opkg / IPK**

```sh
opkg remove luci-app-proxy-guard-pro
opkg remove luci-app-proxy-guard
```

**apk / APK**

```sh
apk del luci-app-proxy-guard-pro
apk del luci-app-proxy-guard
```

حذف، قانون افزونه، RPC، منو و پیوند شروع را پاک می‌کند. مدیر بسته ممکن است تنظیم ویرایش‌شده را نگه دارد. مسدودسازی افزونه رفع می‌شود. برای نگهداری، [خاموش‌کردن صریح](RECOVERY.fa.md) را ببینید.

## پیکربندی نخست

در [راهنمای تنظیم](GUIDED-SETUP.fa.md) ورودی واقعی لایهٔ ۳ LAN را انتخاب و [تنظیمات](USER-GUIDE.fa.md#guide-options) را بررسی کنید. با یک کلاینت و هر دو خانواده شروع کنید. نشانی‌های بسته نمونه‌اند. SOCKS5 واقعی روی `127.0.0.1`، ورودی‌های پروکسی کلاینت و پورت مقصد DNS را بسنجید. پورت بررسی با ورودی پروکسی فرق دارد. DNS پیش‌فرض `53` است. استثناها را دقیق کنید و IPv6 خارج از دامنه را صریح کنار بگذارید. ابتدا **فقط پایش** را اعمال و مسیر واقعی را بررسی کنید.

## ذخیره، اعمال و وضعیت

ویرایش پیش‌نویس است. **ذخیره** برای نشست نگه می‌دارد و **ذخیره و اعمال** بررسی و ثبت می‌کند. پس از خودآزمایی **تا ۳۰ ثانیه** تأیید کنید. بازنشانی فرم را به مقادیر ذخیره‌شده یا موقت بازمی‌گرداند. پاک‌کردن گزارش فقط رویداد و بررسی همین افزونه را پاک می‌کند. وضعیت حدود یک و گزارش حدود پنج ثانیه تازه می‌شود. RPC کند نمایش را عقب می‌اندازد. وضعیت کهنه را با هسته بسنجید و پس از تغییر دسترسی دوباره وارد شوید. [وضعیت و عیب‌یابی](USER-GUIDE.fa.md#guide-troubleshooting) را ببینید.

## مسدودسازی و بازیابی

### بررسی معمول

HTTPS از SOCKS محلی می‌گذرد. تطبیق IPv4 خروجی و SOCKS5 UDP اختیاری‌اند. هدف‌های تازه `https://www.gstatic.com/generate_204|204` و `https://connectivity-check.ubuntu.com/|204` هستند. پیش‌فرض یک وب‌سایت موفق و همهٔ بررسی‌های روشن خروجی و UDP است. سه دور ناموفق خرابی و دو دور موفق بازیابی را تأیید می‌کنند. ۱۰ ثانیه از پایان هر دور حساب می‌شود. فرصت ثابت شروع تا ۱۵۰ ثانیه پس از بوت است و حالت محافظت در این مدت مسدود می‌کند. محافظت راه‌اندازی منتظر سرویس می‌ماند.

در تطبیق خروجی، فقط پایان مهلت هدف اصلی یک HTTPS پشتیبان از همان SOCKS را امتحان می‌کند. دور تازه از اصلی آغاز می‌شود. فیلد خالی برای ipify از `https://4.ident.me/` استفاده می‌کند و دامنهٔ دیگر پشتیبان ندارد. نشانی نادرست و بررسی ناموفق تابع قانون خرابی هستند.

### پایش سرویس کلاینت

هویت فرایند و شنونده تقریباً هر ثانیه سنجیده می‌شود. پیش‌فرض توقف یا راه‌اندازی هر TCP، UDP یا DNS لازم محافظت را فعال می‌کند. می‌توانید خرابی همهٔ موارد لازم را شرط کنید. موارد لازم طبق پیکربندی واقعی کلاینت‌اند.

انتظار پیش‌فرض مسدودسازی ۱۵ ثانیه، بدون آزمون بیرونی است. پس از پایان انتظار و آمادگی سرویس، بررسی تازه در صورت موفقیت ترافیک را آزاد می‌کند. سپس ۶۰ ثانیه پایش تقویت‌شده با دسترسی در حالت سالم و حدود یک ثانیه میان پایان هر دور است. بازیابی و پایش تقویت‌شده به همهٔ HTTPSها و بررسی روشن خروجی و UDP نیاز دارند. خرابی تازه فوراً به انتظار برمی‌گردد. انتظار و پایش کلید جدا و مدت ۱ تا ۳۶۰۰ ثانیه دارند. بررسی بازیابی باقی می‌ماند.

### گزارش اجرا

پایش گزارش را جداگانه زیر پایش سرویس با فاصلهٔ ۱ تا ۱۰ ثانیه روشن کنید. پیام‌های بررسی‌شدهٔ راه‌اندازی، حذف قانون، توقف، خطای شروع و پایان در [سازگاری گزارش](LOG_COMPATIBILITY.fa.md) آمده‌اند. در اولین خرابی گزارش، پایان تازهٔ چرخهٔ جاری، آمادگی سرویس و آزمون تازه می‌توانند مستقیم وارد پایش تقویت‌شده شوند. خرابی در همان پایش، انتظار تنظیمی دارد. نبود فایل، زمان قدیمی یا آینده و لغو نامربوط، انتظار معتبر را حذف نمی‌کند. تأخیر یکنواخت و زمان گزارش محلی روتر است.

### محافظت راه‌اندازی و زمان‌بندی

کلید کلی، حالت محافظت، پایش سرویس و کلید راه‌اندازی لازم‌اند. در تنظیم معتبر، قانون نخست با نام دستگاه نصب و پس از بررسی رابط جایگزین می‌شود. TCP، UDP و DNS لازم باید پیش از انتظار و بازیابی آماده باشند. مسیر واقعی را آزمایش کنید.

هر روز یا روزهای هفته، زمان شروع و پایان متفاوت و اختلاف ثابت UTC را تنظیم کنید. بازهٔ شبانه متعلق به روز شروع است. در بازه دسترسی بیرونی مسدود و استثناها برقرارند. در پایان، با پایش سرویس و بدون خرابی یا انتظار دیگر، بررسی سخت‌گیرانهٔ تازه به پایش تقویت‌شده می‌رود و ۱۵ ثانیهٔ دیگری اضافه نمی‌شود. بدون پایش سرویس، بررسی‌های معمول پیاپی بازیابی لازم‌اند.

## بررسی ارتقا و راه‌اندازی دوباره

1. نسخه، SHA256، وابستگی و اسکریپت نصب را بررسی کنید. دوباره وارد شوید و صفحه، وضعیت و گزارش را بسنجید.
2. کلید، حالت، ورودی، بازه، استثنا و برنامهٔ واقعی را با تنظیم ذخیره‌شده تطبیق دهید.
3. اتصال تازه و موجود، مسدودسازی و بازیابی، LAN، DNS، مدیریت و دروازهٔ دیگر را از یک کلاینت بررسی کنید.
4. گزارش RAM و دسترسی مستقل را حفظ کنید. برای محافظت راه‌اندازی **روتر دارای Proxy Guard** را راه‌اندازی و از کلاینت تحت محافظت بررسی کنید.
5. در Pro کنترل، مجوز خانگی تازه، پورت و Agent را بسنجید. پس از تغییر فریم‌ور، هسته یا ساختار، دوباره موارد مرتبط را بررسی کنید.

## گزارش و عیب‌یابی

۲۰۰ رویداد و ۱۰۰ جزئیات بررسی اخیر نشان داده می‌شوند. فایل RAM با حد اندازه می‌چرخد. `logger` در گزارش سیستم هم ثبت می‌کند. خطای سطح error ممکن است واکنش درست به خرابی باشد. بازیابی، خطای قانون و تازگی وضعیت را بسنجید. [وضعیت](USER-GUIDE.fa.md#guide-troubleshooting)، [حریم خصوصی](PRIVACY.fa.md) و [بازیابی](RECOVERY.fa.md) را ببینید.

بررسی فقط‌خواندنی روتر:

```sh
if command -v opkg >/dev/null 2>&1; then
    opkg status luci-app-proxy-guard
else
    apk info -a luci-app-proxy-guard
fi
/usr/libexec/proxy-guard status
/usr/libexec/proxy-guard logs
```

## آزمون اختیاری مسیر UDP

سرور DNS قابل‌دسترسی IPv4 UDP، پورت، نام پرس‌وجو و مهلت را تعیین کنید. `luci-lib-nixio` قفل و UDP می‌دهد. نبود پشتیبانی باعث رد فعال‌سازی می‌شود. SOCKS5 UDP ASSOCIATE، رلهٔ loopback و شناسهٔ تصادفی DNS به‌کار می‌روند. مبدأ، شناسه، پرسش و کد پاسخ بررسی می‌شوند. کلاینت باید پشتیبانی کند. هدف LAN فقط مسیر LAN را می‌سنجد.

خطای UDP دور را ناموفق می‌کند و در پایش تقویت‌شده فوراً می‌بندد. در انتظار مسدودسازی ارسال نمی‌شود. HTTPS و خروجی روشن جدا بررسی می‌شوند.

## بازیابی فرایند و منابع

مهلت ضربان، کمترین فاصله، تعداد و پنجره تنظیم‌پذیرند. procd حتی با بازیابی ضربان خاموش، سرویس خارج‌شده را برمی‌گرداند. init stop صریح خودکار فعال نمی‌شود و ممکن است مسدودسازی بماند. [خاموش‌کردن صریح](RECOVERY.fa.md) را ببینید.

هر پنج ثانیه ظرفیت همهٔ CPUهای منطقی آنلاین ۱۰۰٪ است. یک CPU از ۲۰، ۵٪ است. بازنشانی شمارنده، تغییر شمار CPU یا هویت فرایند نمونهٔ تازه می‌خواهد. سه فرایند پایش‌شده و فرزندان شمرده می‌شوند. LuCI/rpcd، هسته و پروکسی دیگر جدا هستند. نمونه‌برداری و ضربان مستقل‌اند. گزارش سیستم ممکن است نگه‌داری یا ارسال شود.

## Pro: مدیریت دسترسی VPS

[معماری](PRO-COMPANION.fa.md)، [نصب عامل](LINUX-AGENT-INSTALL.fa.md) و [تأیید راه‌دور](GUIDED-SETUP.fa.md#remote-policy-confirmation) را ببینید.

- پورت محلی سرویس را صریح انتخاب کنید. پنل، API و اشتراک جداگانهٔ انتخاب‌نشده تابع سیستم‌اند. ورودی مشترک IP، پروتکل و پورت با URL یا SNI جدا نمی‌شود. SSH جدا تنظیم می‌شود.
- قانون پیش‌فرض را به ارث می‌برد یا `standard`، `whitelist` یا `observe` می‌گیرد. TCP/UDP، بازه، مبدأ خانگی، ثابت یا ترکیبی، نرخ، جهش، هم‌زمانی، آستانهٔ fallback، مدت تجاوز، مکث و پنجره جدا تنظیم می‌شوند. پورت فعال یک پروتکل هم‌پوشانی نداشته باشد. استاندارد اتصال سالم را نگه می‌دارد. لغو فهرست مجاز روی ورودی موجود هم اثر می‌گذارد.
- SSH به کنترل، ضربان HTTPS جداگانه از SOCKS و نشست مدیریت مجاز نیاز دارد. مدت نجات عمومی تازه `0` تا بازیابی مجوز خانه یا `30` تا `3600` ثانیه است. مقدار صریح قبلی، SSH و قانون سیستم حفظ می‌شوند. [تنظیم اتصال](LINUX-AGENT-INSTALL.fa.md#control-and-path) را ببینید.
- نگهداری `maintenance.enabled` در Agent و مجوز LuCI می‌خواهد. `adapter=systemd` واحد مشخص و `adapter=3x-ui` تأیید `xui_usr1_confirmed` می‌خواهد. `service` باید نام پایش‌شده باشد. صف از ضربان جداست.
- محدودیت دقیق fallback به فایل خصوصی عادی JSONL `reality.telemetry_file` نیاز دارد. ضربان `{"kind":"heartbeat","time":...}` است. رکورد تازه، ثانیهٔ Unix `time`، `kind` (`authenticated` یا `fallback`)، `source_ip`، `source_port`، `port` و `protocol` دارد. fallback دارای `bytes_in` و `bytes_out` افزایشی هم هست. فقط پورت منتخب تطبیق داده می‌شود. محدودیت به تفکیک جهت، مبدأ و پورت است. مالک معتبر غیر root را با `reality.log_uid` مشخص کنید. گروه و دیگران مجوز نوشتن نداشته باشند.

## پیکربندی خام و سیاست واقعی

هر ویرایشگر UCI فایل افزونهٔ خودش، پیش‌نویس نشست، الگو و دانلود را دارد. صحت دستور و آمادگی فعال‌سازی جدا سنجیده می‌شوند. ذخیره پیش‌نویس است و اعمال، بررسی و تأیید محلی یا راه‌دور را انجام می‌دهد. با تغییر در صفحهٔ دیگر دوباره بارگیری کنید. فیلد ناشناخته با هشدار حفظ می‌شود. `default_deny` و `auto_discover` قدیمی محافظت کل میزبان را فعال نمی‌کنند.

`__KEEP_SAVED_SECRET__` رمز ذخیره‌شده را بدون صدور فایل کلید نگه می‌دارد. برای تغییر مقدار تازه وارد کنید. `revision` برای جلوگیری از تکرار در بخش پشتیبان افزایش می‌یابد. جفت‌سازی و بازبینی را در نصب دوباره حفظ کنید. الگو فقط پیش‌نویس را تغییر می‌دهد.

`source_mode=all` همهٔ مبدأها را طبق حالت انتخابی می‌پذیرد و محدودیت استاندارد را بدون استثنای خودکار خانگی یا ثابت اجرا می‌کند. با فهرست مجاز ترکیب نمی‌شود. `source_mode=any` قدیمی رفتار بدون محافظت را حفظ می‌کند. سیاست مؤثر را از وضعیت تأییدشدهٔ دوردست بخوانید. هنگام نبود LuCI، [بازیابی](RECOVERY.fa.md) را ببینید.
