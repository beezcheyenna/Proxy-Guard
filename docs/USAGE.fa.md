# نصب و استفاده

[English](USAGE.en.md) · [简体中文](USAGE.md) · [日本語](USAGE.ja.md) · [Русский](USAGE.ru.md) · [فارسی](USAGE.fa.md)

Proxy Guard را روی روتری با LuCI و firewall4/nftables نصب کنید. قالب بسته را مطابق مدیر بستهٔ میان‌افزار انتخاب کنید.

## دریافت و بررسی

بسته و فایل مجموع بررسی را از یک انتشار دریافت کنید. برای opkg از IPK و برای apk از APK استفاده کنید. وابستگی‌ها را از مخزن سازگار با میان‌افزار بگیرید.

[GitHub Releases](https://github.com/beezcheyenna/Proxy-Guard/releases)

نام فایل دانلودشده را وارد کنید. خط نخست IPK را انتخاب می‌کند. برای APK از نام فایل در توضیح خط بعد استفاده کنید.

```sh
PG_PACKAGE=luci-app-proxy-guard_1.0.0-8_all.ipk
# PG_PACKAGE=luci-app-proxy-guard-1.0.0-r8.apk
awk -v f="$PG_PACKAGE" '$2 == f { print; n++ } END { if (n != 1) exit 1 }' SHA256SUMS > SHA256SUMS.selected &&
sha256sum -c SHA256SUMS.selected
```

بررسی باید برای بستهٔ انتخاب‌شده OK نشان دهد. در macOS می‌توانید `shasum -a 256 "$PG_PACKAGE"` را اجرا کنید و مقدار کامل را با سطر مربوط در `SHA256SUMS` مقایسه کنید.

SHA256 یکپارچگی فایل را با فهرست می‌سنجد. هویت منتشرکننده را جداگانه بررسی کنید و فایل و فهرست را از یک انتشار معتبر بگیرید. برای نصب آفلاین روی میان‌افزار apk، نخست وابستگی‌های هم‌نسخه را نصب کنید.

<a id="installation"></a>

## نصب و حذف

دستورهای متناسب با میان‌افزار خود را به کار ببرید. هنگام آزمایش محافظت، مسیر مدیریتی جداگانه در دسترس داشته باشید.

```sh
opkg install /tmp/luci-app-proxy-guard_1.0.0-8_all.ipk
apk --no-network --allow-untrusted add /tmp/luci-app-proxy-guard-1.0.0-r8.apk
```

```sh
opkg remove luci-app-proxy-guard
apk --no-network del luci-app-proxy-guard
```

<a id="guide-setup"></a>

## پیکربندی نخست

در «سرویس‌ها → Proxy Guard» راهنما را باز کنید و رابط‌های ورودی، محدودهٔ IPv4 و IPv6، استثناهای محلی و درگاه SOCKS را بررسی کنید. نخست حالت فقط پایش را انتخاب کنید. ذخیره و اعمال، خودآزمایی و مهلت ۳۰ ثانیه‌ای تأیید را آغاز می‌کند. در صورت خطا یا تأیید نشدن، تنظیمات بازگردانده می‌شوند.

بررسی رسمی HTTPS به‌صورت پیش‌فرض از طریق SOCKS محلی به نشانی ثابتی متصل می‌شود. بررسی شخص ثالث زمان‌بندی و آستانهٔ جداگانه دارد. تطبیق IPv4 خروجی در ابتدا خاموش است و پس از فعال شدن از نشانی پاسخ رسمی استفاده می‌کند. سرویس پشتیبان شخص ثالث فقط پس از پایان مهلت سرویس اصلی درخواست می‌شود.

پیش‌فرض HTTPS رسمی فاصلهٔ ۳ ثانیه، مهلت ۲ ثانیه و دو شکست یا دو موفقیت پیاپی است. در حالت شخص ثالث فاصلهٔ پیش‌فرض ۱۰ ثانیه و مهلت هر مقصد ۴ ثانیه است. سه دور ناموفق و دو دور موفق پیاپی برای قطع و وصل لازم است. مقصدهای پیش‌فرض gstatic و Ubuntu هستند و در هر دور عادی پاسخ یکی کافی است.

اگر هر دو سرویس متنی IPv4 به پایان مهلت برسند و اتصال سالم باشد، دسترسی می‌تواند برقرار بماند. پس از تأیید عدم تطابق، بازیابی به دریافت IPv4 منطبق نیاز دارد.

تا زمانی که قواعد نیاز به بررسی دارند، دکمهٔ نگه‌داشتن تنظیمات غیرفعال است و شمارش معکوس اولیه ادامه دارد. با پایان مهلت، روتر تنظیمات قبلی را حتی اگر صفحه بسته شده باشد بازمی‌گرداند.

<a id="test-current-proxy"></a>

## آزمایش پراکسی فعلی

«آزمایش پراکسی فعلی» با تنظیمات ذخیره‌نشدهٔ فرم از طریق SOCKS انجام می‌شود و نتیجه، زمان پاسخ و IPv4 خروجی موجود را نشان می‌دهد. تغییر محافظت با «ذخیره و اعمال» انجام می‌شود.

صفحهٔ وضعیت تعداد بررسی‌های ناموفق پیاپی و دلایل فعال مسدودسازی را نشان می‌دهد. خطای زیر آستانه ممکن است دسترسی را قطع نکند. زمان‌بندی، درخواست API و خطای اتصال می‌توانند هم‌زمان فعال باشند.

API محلی در نصب تازه غیرفعال است. پس از فعال‌سازی می‌توانید با UUID نمایش‌داده‌شده در LuCI وضعیت را بخوانید، عیب‌یابی کنید و مسدودی مدت‌دار را آغاز یا لغو کنید.

## آزمون محافظت هنگام راه‌اندازی

یک مسیر مدیریت مستقل در دسترس نگه دارید و روترِ اجراکنندهٔ Proxy Guard را راه‌اندازی مجدد کنید. از دستگاه تحت محافظت بررسی کنید که هنگام راه‌اندازی روتر، ترافیک اینترنت مسدود بماند و فقط پس از موفقیت بررسی‌های بازیابی دوباره برقرار شود.

<a id="local-api"></a>

## رابط محلی API

API کنترل محلی را در LuCI فعال کنید، تنظیمات را ذخیره و اعمال کنید و در صورت نمایش پنجرهٔ تأیید، تغییرات را تأیید کنید. **UUID رابط API** را از همان زبانه کپی کنید. این UUID مجوز دسترسی به هر چهار مسیر است. با خاموش و روشن کردن API، UUID تازه‌ای ساخته می‌شود.

درخواست‌ها را از شبکهٔ محلی به نشانی HTTPS فعلی مدیریت روتر بفرستید. در «نشانی تازه‌سازی API»، ضربان عادی یا عیب‌یابی کامل `/f` را انتخاب کنید.

| روش HTTP | مسیر پس از `/cgi-bin/proxy-guard-api` | کاربرد |
| --- | --- | --- |
| GET | `/status` | خواندن وضعیت محافظت و مسدودی‌های فعال API |
| GET | `/diagnostics` | اجرای بررسی انتخاب‌شده از طریق SOCKS و بازگرداندن نتیجه |
| POST | `/block` | آغاز مسدودی مدت‌دار |
| POST | `/cancel` | لغو مسدودی با شناسهٔ درخواست |

به جای `router.example` نشانی HTTPS مدیریت روتر و به جای `YOUR_UUID` مقدار نمایش‌داده‌شده در LuCI را بنویسید.

```http
GET /cgi-bin/proxy-guard-api/diagnostics HTTP/1.1
Host: router.example
Authorization: Bearer YOUR_UUID
```

```sh
curl -H 'Authorization: Bearer YOUR_UUID' 'https://router.example/cgi-bin/proxy-guard-api/diagnostics'
```

هر دو مسیر POST از `Content-Type: application/json` استفاده می‌کنند. بدنهٔ `/block` می‌تواند `{"seconds":120,"request_id":"sample-block-01"}` باشد. بدنهٔ `/cancel` برابر `{"request_id":"sample-block-01"}` است. در صورت حذف مدت یا تعیین صفر، مدت پیش‌فرض اعمال می‌شود. در صورت حذف شناسه، روتر آن را می‌سازد. مسدودی مدت‌دار به فعال بودن حالت محافظت نیاز دارد. تکرار یک درخواست فعال با همان شناسه و مدت، زمان پایان آن را تغییر نمی‌دهد. پس از لغو نیز سایر دلایل فعال مسدودی اعمال می‌شوند.

پاسخ احرازشده شامل `uuid` است. در تشخیص موفق، `diagnostics.headers` جفت‌های `name` و `value` برای سرآیندهای `X-PGHB-*` را به‌ترتیب پاسخ برمی‌گرداند. تکرارها و مقادیر رشته‌ای حفظ می‌شوند. مقادیر خارج از UTF-8 با `encoding: "base64"` مشخص می‌شوند. HTTP 401 به معنی UUID مفقود یا نامعتبر، 403 به معنی API خاموش یا دسترسی‌ناپذیر از شبکهٔ فعلی، 429 به معنی دورهٔ انتظار یا رسیدن به سقف درخواست، و 502/504 به معنی شکست یا پایان مهلت بررسی است.

کاربران LuCI با مجوز تنظیم افزونه می‌توانند UUID درخواست‌های احرازشده را در گزارش رویدادها ببینند. هنگام اشتراک‌گذاری گزارش، UUID را بپوشانید.
