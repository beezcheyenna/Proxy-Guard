# 通常版と Pro の機能比較

[English](EDITION-MATRIX.en.md) · [简体中文](EDITION-MATRIX.md) · [日本語](EDITION-MATRIX.ja.md) · [Русский](EDITION-MATRIX.ru.md) · [فارسی](EDITION-MATRIX.fa.md)

通常版 `0.3.0-21` はルーターの接続を保護し、Pro `0.3.1-5` は VPS の選択したサービスポートのアクセス管理を追加します。パッケージと版番号は独立しています。

| 項目 | 通常版 | Pro |
| --- | --- | --- |
| 配備 | OpenWrt ルーター | ルーター拡張と Linux Agent。Worker/Tunnel は任意 |
| プロキシ検査 | ローカル SOCKS 経由の HTTPS、任意の IPv4 出口・SOCKS5 UDP | 通常版の検査と VPS 出口候補の取り込み |
| ローカルルール | 入口、送信元範囲、例外、IPv4/IPv6 TCP/UDP | 通常版と共通 |
| クライアント | PassWall、PassWall2、OpenClash、Nikki、HomeProxy の検証済み版・モード | 通常版と共通 |
| 保護手順 | 障害しきい値、遮断待ち、強化監視、起動時・定時保護 | 任意のリモート正常性条件とメンテナンス後の復旧 |
| 画面 | 状態、イベント・検査ログ、5 言語、ウィザード、原文設定、自己診断と限定的な復旧 | ポート、認証接続、リモート状態、所定操作 |
| リモートポート | — | 許可リスト、レート制限、観察をルールごとに選び、送信元としきい値を設定 |
| SSH | — | 明示的に有効化。2 経路途絶後の継続または期限付き救済 |
| メンテナンス | — | VPS 再起動と対応 Xray 再起動を個別許可。対応 3x-ui アダプターも利用可能 |

## 個別更新

Pro は通常版の下限と基本 API を検査します。条件を満たせば Pro のみ更新できます。通常版のセキュリティ、動作、ファームウェア互換性の修正には通常版の更新が必要です。Pro は 5 言語の専用ページ、ポリシー確認、原文エディターを持ちます。

先に通常版を更新した場合、フックがインストール済みの旧 Pro に必要な旧辞書の項目を保存します。新しい Pro を入れると一時辞書を削除します。Agent と Worker の機能は個別に確認し、新しい機能には対応する配備の更新が必要です。

## 現在の範囲

新規インストールでは通常版の保護と Pro は無効です。SSH とメンテナンスは個別に許可します。検出は候補を示し、未選択ポートは元のファイアウォールに従います。既定の制御と家庭 IP 同期は IPv4 です。IPv6 のデータ面は別途確認します。

配備はルーター ID 1 組と Agent を中心に構成します。実構成とクライアントを確認してください。正確なフォールバック分類には信頼できる構造化データが必要です。プロセス、ポート、起動ログに加え、実プロキシ要求を確認します。[互換性](COMPATIBILITY.ja.md) を参照してください。

## このリリースの最小互換条件

| コンポーネント | リリースまたは識別子 | 要件 |
| --- | --- | --- |
| 通常版 IPK | 0.3.0-21 | LuCI、opkg、firewall4/nftables、対応依存関係 |
| Pro IPK | 0.3.1-5 | 通常版 **≥ 0.3.0-13**、基本 **API 1** |
| 通常版 APK | 0.3.0-r21 | 対応 SDK、apk、LuCI、firewall4/nftables |
| Pro APK | 0.3.1-r5 | 通常版 **≥ 0.3.0-r20**、基本 **API 1** |
| VPS Agent | **v3** | 制御プロトコル、機能、確認応答を検査 |
| Worker npm プロジェクト | **0.2.0** | v3 応答を中継・検証。npm 版はツールの識別子 |

依存関係と API 定数は [package/Makefile](../package/Makefile) を参照します。IPK と APK には各形式の版表記を使います。下限はインストール条件です。[対応リリースのソース（英語）](https://github.com/beezcheyenna/Proxy-Guard/releases/tag/v0.3.0-21-pro-0.3.1-5) から Agent と必要な Worker を取得し、タグ・コミットを記録します。配備された Worker と `package.json` の版は別に確認します。

### 更新するコンポーネント

| 変更 | 対応 | 非互換時 |
| --- | --- | --- |
| Pro の UI、翻訳、API 1 内の修正 | 互換通常版で Pro のみ更新 | 基本版の非互換をインストールまたは起動時に拒否 |
| API 1 を維持した通常版修正 | 通常版のみ更新 | 新しい主要 API は別途確認 |
| ポート、送信元、試行適用機能 | Agent を先に更新。Cloudflare 使用時は Worker も更新して確認 | `per_rule_modes`、`source_modes_v2`、`policy_confirmation` の不足で適用拒否 |
| プロトコルまたは中継応答の不一致 | 同一リリースのソースで疎通確認。直接 HTTPS は Agent を使う | 失敗を表示し、実ポリシーを確認 |
| VPS 出口候補の取り込み | Agent と制御経路がスキーマ 1 に対応 | 非対応・無効の候補を拒否。通常版の疎通検査は継続 |

Pro の稼働には互換通常版を残します。適用失敗後も以前のルールが残る場合があります。[復旧](RECOVERY.ja.md) の手順でリビジョン、確認待ち、実ルールを照合してください。
