Установите Proxy Guard на маршрутизатор с LuCI и firewall4/nftables. Выберите формат пакета, который использует ваша прошивка.

## Первичная настройка

Откройте «Службы → Proxy Guard». Проверьте в мастере входные интерфейсы, область IPv4 и IPv6, локальные исключения и порт SOCKS. Сначала используйте режим наблюдения. После сохранения и применения пройдёт самопроверка. На подтверждение даётся 30 секунд. Если проверка не пройдена или подтверждения нет, настройки откатываются.

Требуются LuCI, firewall4 и nftables. Для OpenWrt 24 используется IPK, для OpenWrt 25.12 — APK. Для iStoreOS и ImmortalWrt сверяйте пакетный менеджер и зависимости ядра своей прошивки.

Защищается только трафик, который проходит через маршрутизатор. Сначала проверьте на одном устройстве входной интерфейс, IPv4, IPv6, DNS и управление. В одной подсети обратный трафик может пройти мимо маршрутизатора.

Пока правила требуют проверки, кнопка подтверждения недоступна. Исходный отсчёт продолжается. По истечении времени маршрутизатор восстановит прежние настройки, даже если страница уже закрыта.

## Режимы работы

- **Только наблюдение** записывает сбои и оставляет доступ в Интернет открытым.
- **Защита** блокирует Интернет для выбранной области после подтверждённого сбоя. Для блокировки во время запуска маршрутизатора выберите защиту при загрузке.
- **Защита по расписанию** работает ежедневно или в выбранные дни недели. Используется фиксированное смещение UTC, по умолчанию UTC+00:00.

Контроль служб и журналов может обнаружить перезапуск клиента и запустить проверки восстановления. Сторожевой процесс следит за самим Proxy Guard. Для отдельной проверки пути UDP включите проверку UDP через прокси.

## Проверить текущий прокси

Официальная проверка HTTPS по умолчанию обращается к фиксированному адресу через локальный SOCKS. У сторонней проверки свои интервалы и пороги. Проверка исходящего IPv4 изначально выключена и после включения по умолчанию использует адрес из официального ответа. Резервный сторонний IP-сервис опрашивается только при тайм-ауте основного.

Кнопка «Проверить текущий прокси» использует несохранённые настройки формы и подключение через SOCKS. Она показывает результат, задержку и доступный исходящий IPv4. Изменения защиты вступают в силу после сохранения и применения.

В разделе «Настройка и диагностика» под формой можно проверить параметры и рабочую среду, протестировать текущий прокси или посмотреть отчёт без конфиденциальных данных. Здесь же можно заново запустить мастер, отредактировать конфигурацию UCI, загрузить последние подтверждённые настройки или вернуться к настройкам по умолчанию.

В разделе «Настройка и диагностика» откройте «Проверить текущий прокси» и нажмите «Запустить подробную диагностику» в диалоговом окне. Маршрутизатор один раз запросит `/f` через локальный SOCKS и покажет заголовки ответа `X-PGHB-*`.

## Проверки и восстановление

Официальная проверка HTTPS по умолчанию выполняется с интервалом 3 секунды и тайм-аутом 2 секунды. Два сбоя подряд подтверждают отказ, два успеха подряд — восстановление. Для сторонних сайтов интервал составляет 10 секунд, тайм-аут одной цели — 4 секунды. Требуются три неудачных цикла или два успешных. В обычном цикле должна ответить хотя бы одна цель.

При включённом наблюдении блокировку могут вызвать остановка выбранной службы или распознанное событие в журнале клиента. Проверки восстановления начинаются после выполнения настроенных условий. После восстановления усиленное наблюдение может работать с меньшим интервалом. Повторный сбой в этот период может снова закрыть доступ.

Для блокировки по расписанию нужно включить общий переключатель и режим защиты. Если одновременно действуют расписание, блокировка API и сбой проверки, доступ возвращается после устранения всех причин.

## Блокировка и восстановление

В состоянии отображаются число последовательных неудачных проверок и действующие причины блокировки. При сбое ниже порога доступ может сохраниться. Расписание, запросы API и неполадки подключения могут действовать одновременно.

Локальный API по умолчанию выключен. После включения используйте UUID из LuCI. [Запросы к локальному API](USAGE.ru.md#local-api)

В журнале событий можно раскрыть подробности последних проверок соединения и историю восстановления. Кнопка «Очистить журналы и историю восстановления» удаляет все три вида записей. Текущее состояние восстановления остаётся видимым, а операция очистки записывается в журнал событий.
