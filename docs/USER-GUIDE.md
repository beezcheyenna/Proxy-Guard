<a id="guide-setup"></a>

## 安装与首次设置

1. 通过 LuCI 软件包页面安装匹配的普通版 IPK；需要 VPS 扩展时，再安装兼容的 Pro。
2. 打开“服务 → Proxy Guard / 代理连接保护”，完成引导，核对 SOCKS、客户端、入口及 IPv4 / IPv6 范围和例外。先以“仅监测”启用检查并保存应用，按提示确认，再核对检测结果。
3. 准备启用阻断时，切换到保护模式，再点击“保存并应用”。自检通过后，在 **30 秒内确认**；自检失败或未按时确认时回退配置。正常的代理故障按阻断保护处理。

新装的保护总开关、出口 IPv4 校验和定时保护默认关闭。勾选和编辑只修改草稿；“保存”只暂存，**“保存并应用”才提交**。设置页可重新运行引导、载入上次确认的配置或编辑原始 UCI。

## 系统要求与保护范围

<a id="guide-requirements"></a>

### 支持哪些系统和代理客户端？

路由器需使用 **opkg + LuCI + firewall4/nftables**，并能从匹配的软件源安装 Lua、ucode、curl 等依赖。已进行兼容测试的版本包括 OpenWrt `24.10.4`、ImmortalWrt `24.10.4` 和 iStoreOS `24.10.8` 的指定版本。

已适配 PassWall、PassWall2、OpenClash、Nikki、HomeProxy；支持情况取决于客户端版本、内核及转发模式。部分 sing-box redirect / HomeProxy TUN 组合存在限制，请先核对[兼容表](COMPATIBILITY.md)。IPK 不支持使用 APK 的固件分支，也不支持仅有 fw3/iptables 的系统。`all` 包不表示所有硬件和架构都已验证。

Pro 的 Linux Agent 需要 Python `3.10+`、nftables 及所需内核能力；支持 systemd / OpenRC。已进行兼容测试的发行版包括 Ubuntu、Debian、Rocky Linux、Alpine Linux 的指定版本，详见[Linux 安装](LINUX-AGENT-INSTALL.md)。

<a id="guide-scope"></a>

### 哪些流量能保护，哪些拓扑需要留意？

- **只能阻断经过本机的流量。** 同网段无 NAT 旁路由的回程可能绕过本机；这部分流量无法被拦截。仅经交换使用其他网关的设备不属于保护路径。
- 对已选设备或网段，保护可覆盖实际经本机的 IPv4/IPv6、TCP/UDP 双向流量及已有连接；路由器本机主动发起的流量不属于这些客户端的保护范围。
- 插件不修改 NAT、网络接口、系统路由、DNS 或代理客户端配置。局域网、DNS 和管理访问的保留取决于正确的范围与例外配置。
- 流量卸载、桥接过滤及不兼容内核能力可能阻止启用保护。厂商硬件加速、物理网口、多入口、VPN 和容器路径须实机核验。
- 一次检测成功不代表所有网站、UDP 应用和 IPv6 出口正常。采样间隔内的短暂变化、未适配日志和新上游版本也有识别限制。
- 启用前应核对实际拓扑和流量路径。建议先用一台设备检查故障阻断、恢复、LAN、DNS、管理及其他网关设备，再扩大范围。

### Pro 需要部署什么？能否单独升级？

Pro 需要兼容的普通版和另行部署的 Linux VPS Agent。控制链路可选直接 HTTPS 或 Cloudflare；安装扩展不会自动创建云端资源。接口兼容时可单独升级 Pro；普通版本身的安全、状态机、固件兼容或共享翻译修复仍可能需要更新普通版。

## 配置与运行

<a id="guide-options"></a>

### 关键设置怎么选

| 设置 | 填写与使用要点 |
| --- | --- |
| 工作模式 | “仅监测”只检查并记录，不阻断；“保护模式”才会按故障或定时条件限制流量。 |
| 本机 SOCKS | 使用代理客户端实际提供的本机 SOCKS5 端口。默认 `1070` 只是示例，插件不会创建代理。 |
| 入口设备 | 选择受保护流量实际进入的三层设备，例如承担路由的 LAN 桥；不要直接把所有物理网口都选上。 |
| 保护地址 | IPv4 填实际客户端地址或网段；IPv6 单独确认。只选一台 IPv4 设备，不会自动限定它的全部 IPv6 地址。 |
| 局域网例外 | 只保留实际需要访问的局域网网段，包括需要保留的跨网段服务；范围过大会削弱保护。 |
| 代理入口与 DNS 端口 | 填真实使用的端口。代理入口用于防止显式代理绕过；DNS 例外须对应实际目标端口，两者不能重叠。 |
| 出口 IPv4 校验 | 默认关闭。启用时填可信的预期出口，不能把任意新检测到的地址自动当作可信值。 |
| 服务、日志和开机保护 | 新装的已保存配置默认关闭这些功能；引导可能根据已识别的客户端推荐开启服务监视。以引导摘要和已应用配置为准。开机保护还要求总开关、保护模式和服务监视均已开启。 |
| 定时保护 | 默认关闭且没有预填计划；核对时间、重复星期和固定 UTC 偏移后再应用。 |

HTTPS 检测目标每行一个，格式为 `https://域名/路径|预期状态码`，例如 `https://www.gstatic.com/generate_204|204`。竖线后的 `204` 是预期 HTTP 状态码，不是网址的一部分。可配置 2–4 个目标，并设置常规模式下每轮至少成功几个；默认至少成功 1 个。增强监测期间要求全部目标成功。请求经本机 SOCKS，目标故障或限流也可能影响结果。

出口校验启用后，常规地址默认使用 ipify；可选的 Cloudflare 检查只在开机代理就绪和每次中断恢复后额外尝试一次，同一中断的信号会合并，不进行每日或持续轮询。它还受出口校验开关控制。不要将 Cloudflare trace 地址另行加入高频检测列表；任何第三方接口都不能保证永久可用或不限流。

Cloudflare 超时或不可用本身不构成阻断依据，常规检查仍须通过；若它返回的出口与预期不一致，则按故障处理。

**建议首次验收顺序：**

1. 先只选择一台可控客户端，核对它的网关、IPv4 / IPv6 路径及 LAN、DNS、管理例外。
2. 以仅监测模式启用，保存并应用，按提示确认；核对网站结果、可选出口校验与已启用的客户端服务检查。
3. 切换保护模式，保存并应用；自检通过后在 30 秒内确认，保留独立的管理或控制台入口。
4. 在自己可控的维护窗口模拟一次代理故障和恢复，检查新连接、已有连接及需要使用的 IPv4 / IPv6、TCP / UDP 路径，同时核对 LAN、DNS、管理和其他网关设备。
5. 验收后再扩大范围、添加定时或启用开机保护。开机保护应另做重启验收；自检不能代替这些实际通路检查。

<a id="guide-detection"></a>

### 检测、阻断与恢复

#### 常规连通性检测

连通性检查固定经过配置的本机 SOCKS，不回退直连。出口 IPv4 一致性校验默认关闭；启用后须设置可信的预期地址。Pro 可从 VPS 读取地址候选，但网卡或面板地址不一定等于代理真实出口，导入后仍需核对、保存并应用。

常规连通性检测默认在每轮完成后等待 10 秒，请求耗时另计；连续失败 3 轮判定故障，连续成功 2 轮确认恢复。这些值均可配置。页面约每秒刷新状态，不代表常规外网检测每秒执行。

固定启动宽限默认截至路由器开机后 150 秒，保护模式在等待期间保持阻断。开启开机保护时，改为等待所需服务就绪，再走配置的阻断等待与恢复验证。

#### 服务与日志监视

开启客户端服务监视后，默认已纳入监视的任意 TCP、UDP 或 DNS 组件停止或重启均可触发保护。日志监视需在服务监视下另行开启，只识别已适配的上游消息；界面语言不改变日志识别范围。可选 UDP 通路检查需要 SOCKS5 UDP ASSOCIATE 支持。

服务监视以当前客户端配置中实际需要的组件为准；未配置或不需要的 UDP / DNS 项不会一律视为故障。无法识别客户端时，应检查适配与配置，不能把“未纳入检查”当成“已验证正常”。

#### 阻断与恢复

服务监视触发保护时，默认恢复顺序为：

1. **阻断等待 15 秒**，期间不做外网验证。
2. 等待结束、服务就绪后，重新验证代理；通过恢复条件才放行。
3. 放行后进入 **60 秒增强监测**。这 60 秒内，正常时可以联网；再次检测到故障，重新阻断并进入等待。

增强监测在每轮完成后约等 1 秒再开始下一轮，请求耗时另计。此阶段要求所有 HTTPS 目标、已开启的出口 IPv4 校验和 UDP 检查都通过；任一失败即重新阻断，不沿用常规模式的最少成功目标数或连续失败阈值。

等待、增强监测及其时长均可配置。日志触发后，要等当前启动周期有效的完成消息、服务恢复和新的代理验证通过，首次恢复才跳过额外等待。定时窗口结束时，只有已开启服务监视、且没有其他故障或未完成的等待，才使用同样的恢复流程。增强监测中再次出现故障，仍重新阻断并执行等待。开机保护须另外启用。详见[检测流程](USAGE.md)与[日志兼容](LOG_COMPATIBILITY.md)。

<a id="guide-schedule"></a>

### 定时、状态与语言

#### 定时安排

定时保护新装默认关闭，**不预填时间或星期**。可选择每天重复，或每周任意多个星期；跨午夜窗口归属开始当天。时区使用固定 UTC 偏移，默认 `UTC+00:00`，不自动切换夏令时。升级会保留已保存的时区与定时计划。

例如仅选择星期一、开始 `22:00`、结束 `06:00`，表示在所选 UTC 偏移下，从星期一晚阻断到星期二早；无需额外勾选星期二。这个例子不会自动生成计划。这里只阻断所选客户端的外网，LAN、DNS 和管理仍按例外配置保留。

#### 状态与日志

页面自动刷新状态、事件与检测详情。进程守护和有限自动恢复只处理插件自身异常；正常的代理故障仍按保护流程处理。日志位于内存，路由器重启后会丢失；系统另行配置的持久化日志不受此设置控制。

#### 界面语言

界面随 LuCI 语言设置提供 **简体中文、英语、日语、俄语和波斯语**。本页顶部可切换说明语言。

<a id="guide-troubleshooting"></a>

#### 状态应该怎么看？

| 状态或提示 | 含义与下一步 |
| --- | --- |
| 已关闭 | 本插件未提供阻断保护；检查总开关和已应用配置。 |
| 仅监测 | 正在观察，不限制上网；日志中有故障也不会安装阻断策略。 |
| 已阻断或定时保护中 | 查看具体原因、当前计划和服务状态；正确响应故障也会产生告警。 |
| 阻断等待倒计时 | 这段时间不能上外网，也不进行外网验证；等待结束后仍须通过恢复检查。 |
| 已恢复，增强监测中 | 正常时可以联网；出现新的故障会再次阻断并执行等待。 |
| 等待 LAN 接口 | 核对所选设备名及接口实际状态；插件不会替你创建或启用网口。 |
| 状态过期、失联或规则未确认 | 当前保护尚不能确认。保留报错并检查进程、规则和配置，不要根据旧绿色状态判断正常。 |

#### 升级、重装与排错

升级前保存本插件配置；Pro 的配对密钥、Agent 私有配置和证书也应单独安全备份。升级会保留已有选择，新的默认值不会自动替换旧设置。安装同版本修订包时，opkg 可能认为已经安装；先核对来源与校验值，再按[安装参考](USAGE.md#安装升级和卸载)选择同版本重装方式，不要绕过依赖检查。Pro 可独立升级的前提是基础接口兼容，远端新功能仍可能要求更新 Agent 或 Worker。

菜单缺失、页面异常或 RPC 找不到对象时，先保留完整安装输出，再重新登录 LuCI 并刷新页面。正常安装应由包内钩子完成缓存清理及 RPC 重载；重新登录后仍异常，应继续排查安装失败和依赖，不要额外放宽 ACL 或把手工重载服务当作安装成功的证据。

可在自己的路由器上只读查看：

```sh
opkg status luci-app-proxy-guard
/usr/libexec/proxy-guard status
/usr/libexec/proxy-guard logs
```

“清空日志”只删除本插件日志，不清除客户端源日志、不恢复联网。需要解除本插件保护时，关闭总开关并保存应用；杀死进程或卸载不能作为安全的临时放行方法。分享诊断内容前删除真实地址、密钥、订阅链接及认证头；涉及安全漏洞时使用下方私密反馈邮箱。

<a id="guide-pro"></a>

### Pro：VPS 访问、SSH 与远程维护

Pro 同步认证的家庭公网 IP，并对选定 VPS 服务端口应用访问策略。可将 VPS 服务健康作为本地恢复的附加条件；本机代理验证仍然必须通过。 可选带宽限制仅适用于由可信遥测确认的回落连接。

#### 端口与策略

Pro 只管理用户明确添加并启用的 VPS 本机服务端口。监听端口发现只提供候选，未选端口继续由原有防火墙管理，不自动接管 Docker 转发或整机端口。

每条规则可选择 **仅白名单、标准防滥用、仅观察**，并分别配置来源、连接阈值和时间。远端策略默认另有 **60 秒确认**，未确认时恢复先前策略。面板、API、订阅与代理共用同一端口时，也可能一起受规则限制。

工作模式与来源设置是两层选择：“所有来源”在标准模式下仍执行资源限制；旧配置中的“不限制”会完全绕过该端口保护。仅白名单模式不能搭配所有来源。家庭或静态白名单是否豁免标准限制，取决于该规则选择的来源方式。

仅观察模式不拦截所选业务端口；单独启用的 SSH 托管仍按自身设置生效。

#### SSH 应急访问

SSH 默认不纳管，远程维护默认关闭。若主动启用 SSH 托管，两路认证心跳均失联达到配置时间（默认 60 秒）后，可触发应急访问。新配置默认允许公网应急，持续到家庭授权恢复；可改为限时或限定管理来源。持续开放会增加公网暴露时间；限时到期且无可用来源时可能无法重新登录。SSH 身份验证、系统防火墙和上游安全组仍然生效。

#### 控制连接

控制链路可选直接 HTTPS，或 Cloudflare Worker 与 Tunnel/VPC，用于认证和策略协调，本身不承载代理业务流量。控制请求必须绕过代理，并由用户确认直连分流；插件不会代改路由或分流设置。独立代理路径心跳则经本机 SOCKS 验证代理通路。默认控制配置使用 IPv4；IPv6 流量保护不代表 IPv6 云端控制已经验证。部署步骤见[Pro 配套说明](../companion/README.md)。

独立代理路径有自己的心跳密钥和 Agent HTTPS 入口；直接 HTTPS 模式可复用同一 Agent 根地址，但请求必须分别走直连控制与 SOCKS 代理路径。Cloudflare 模式不能把 Worker 地址当作该独立入口。地址和密钥对应关系见[连接配置表](LINUX-AGENT-INSTALL.md#control-and-path)。

#### 固定远程维护

远程维护默认关闭。须在路由器和 VPS Agent 两端授权对应操作，才能请求重启 VPS 或受支持的 Xray 代理内核。请求被接收不等于恢复完成，需查看后续验证结果；插件不执行任意远程命令。

#### Pro 首次部署顺序

1. 先完成普通版的本地保护验收，再安装兼容的 Pro。
2. 在目标 Linux VPS 安装 Agent，核对真实服务、端口、依赖和原有防火墙；保留 SSH 或控制台管理通路。
3. 选择直接 HTTPS 或 Cloudflare 控制链路，分别配对所需凭据。确认控制请求绕过代理；若需要 SSH 应急功能，再配置独立的代理路径 HTTPS 心跳。
4. 先读取认证、授权和服务状态；监听发现仅提供端口候选。只添加需要管理的端口，核对面板、订阅及 SSH 是否共用入口。
5. 保存并应用，核对 VPS 的临时策略结果，并在远端确认倒计时内确认，默认 60 秒。它与普通版的本地 30 秒确认是两个独立流程。
6. 最后按需启用 SSH 托管、远端健康附加条件或远程维护，分别完成对应检查。停用同步不等于删除 VPS 规则，移除规则须走专门的准备、应用和确认流程。
